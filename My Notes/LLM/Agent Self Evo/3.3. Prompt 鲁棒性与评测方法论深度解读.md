# Prompt 鲁棒性与评测方法论深度解读

> 范围：[[3. Adaptive prompt for diff LLM]] 类别四"评测与鲁棒性（背景）"的 7 篇工作（PromptRobust / PromptBench / Brittlebench / POSIX / Multi-Prompt Eval / AgentBench / AgentBoard）。
> 主线问题：这些论文不直接做"适配"，但共同回答了一个更根本的问题——**为什么一份 prompt 的单点评测分数不可信**，从而构成"为什么需要跨模型/跨 prompt 适配"的实证基础。

## 1. PromptRobust —— 首个把"prompt 本身"当攻击对象的鲁棒性基准

**论文**：Zhu et al.，2023→2024（[arXiv 2306.04528](https://arxiv.org/abs/2306.04528)）

### 1.1 工作定位

"we introduce PromptRobust, a comprehensive benchmark designed to evaluate the robustness of LLMs to perturbations in **prompts**"——首次显式以 prompt（而非输入样本）为攻击对象。总规模：4,788 个对抗 prompt，9 个 LLM，8 类任务，13 个数据集。

### 1.2 四级攻击分类法——核心方法学

沿用 7 种已有 NLP 对抗攻击技术，专门应用在 **prompt 部分**：

- **字符级**（2 种）：TextBugger（词内加/删/重复/替换/置换字符模拟拼写错误）、DeepWordBug（同类字符扰动）
- **词级**（2 种）：BertAttack（用 BERT 找上下文相似词替换）、TextFooler（同义词替换以误导 LLM）
- **句子级**（2 种）：StressTest（prompt 末尾追加"and true is true"/"and false is not true"等重复扰动 ×5）、CheckList（追加 50 个由字母数字组成、长度为 10 的随机串）
- **语义级**（1 种）：选取 6 种常见语言（中/法/阿/西/日/韩），每数据集每语言构造 10 个 prompt 再翻译回英文（"translated into English, introducing linguistic nuances and variations"）——**注意：这是机器翻译式扰动，不是 LLM 改写或回译**

### 1.3 评估指标：PDR 与 APDR

$$
\text{PDR}(A,P,f_\theta,D)=1-\frac{\sum_{(x,y)\in D}M[f_\theta([A(P),x]),y]}{\sum_{(x,y)\in D}M[f_\theta([P,x]),y]}
$$

$A$ 为攻击，$P$ 为 prompt，$f_\theta$ 为模型，$D$ 为数据集，$M$ 为评估函数（分类取 0/1 indicator，阅读理解取 F1，翻译取 BLEU）。PDR 是**相对下降率**，已按基线归一化，可跨模型/任务/攻击比较；负 PDR 表示对抗 prompt 反而提升性能。

$$
\text{APDR}_A(A,D)=\frac{1}{|\mathcal{P}||F|}\sum_{P\in\mathcal{P}}\sum_{f_\theta\in F}\text{PDR}(A,P,f_\theta,D)
$$

在 4 种 prompt 类型（zero-shot/few-shot/role-oriented/task-oriented）和全部 LLM 上取平均。

### 1.4 结论

词级攻击最强（平均下降 33%），字符级次之（20%）；至少 85% 的对抗 prompt 经人工标注确认"语义保持可接受"——即模型性能下降不是因为任务变难了，纯粹是表面形式扰动导致。这是后续所有"多 prompt/多扰动评估"工作的直接动机：**即便模型不变、样本语义不变，prompt 表面形式的微小变化也能让单点性能度量失真**。

## 2. PromptBench —— 把 PromptRobust 工程化为统一评估库

**论文**：Zhu, Zhao, Chen, Wang & Xie，JMLR 2024（[arXiv 2312.07910](https://arxiv.org/abs/2312.07910)，[代码](https://github.com/microsoft/promptbench)）

### 2.1 组件

prompt construction（模板构造）、prompt engineering（CoT/角色/风格等变体）、dataset and model loading、**adversarial prompt attack**（直接继承 PromptRobust 的 4 级 7 攻击）、dynamic evaluation protocols（动态评估协议）、analysis tools（分析工具）。

### 2.2 定位与"超越"

定位是"a unified library"而非新基准——支持的 LLM/任务/协议范围比单篇 PromptRobust 更广，且支持用"curated adversarial prompts"做更高效的鲁棒性评估。简言之：PromptRobust 回答"prompt 扰动会不会伤害性能"，PromptBench 提供"怎么系统化、可复现地测这件事"的工具箱。

## 3. Brittlebench —— 用方差分解量化"扰动到底占多少"

**论文**：Romanou et al.，Meta FAIR + EPFL + Northeastern，2026（[arXiv 2603.13285](https://arxiv.org/abs/2603.13285)，代码即将发布）

### 3.1 "语义保持"的行为化定义

不用字符串相似度定义"语义保持"，而是行为化定义（附录 A.2）："we define 'semantic-preservation' behaviorally, on the basis of the task at hand"——对每个 benchmark，**原始问题和扰动后问题的金标答案必须保持一致**。

### 3.2 6 大类 15 种扰动

1. **词操作（Word manipulation）**：typos（拼写错误）、word splits（词拆分/合并）、insertion of additional spaces（插入多余空格）
2. **上下文增强（Prompt augmentation）**：personas（角色设定）、emotional phrases（情绪短语）、explanatory paraphrasing（解释性改写）
3. **特殊符号填充（Prompt padding）**：首尾加空格/引号/换行等特殊字符
4. **改写（Paraphrasing，三种风格）**：lexical（词汇替换）、syntactic（句法改写）、rule-free（自由改写）——GPT-4o 生成，人工+GPT-4o 判官双校验
5. **数学扰动（Math perturbations）**：针对数学表达式，避免破坏表达式本身
6. **代码扰动（Code perturbations）**：针对代码片段

覆盖 6 个 benchmark（MMLU/ARC/TruthfulQA/MathQA/GPQA/LogiQA，基于 lm-evaluation-harness）与开源+商用模型（Llama3.x/Qwen3/Claude 4.5 Opus/GPT-5）。

### 3.3 核心方法：方差分解

把"模型是否答对"（$Y\in\{0,1\}$）的总方差按数据难度 vs 扰动分解：

$$
\text{Var}(Y)=\underbrace{\text{Var}_D(\mathbb{E}_P[Y|D])}_{V_{\text{data}}}+\underbrace{\mathbb{E}_D[\text{Var}_P(Y|D)]}_{V_{\text{brittleness}}}
$$

- $V_{\text{data}}$：数据难度方差（对所有扰动取期望后，各题本身的难度差异）
- $V_{\text{brittleness}}$：扰动引入方差（同一题在不同扰动下的预测波动）

实证：开源模型中扰动方差占总方差约 **50%**，商用模型约 25%——即接近一半的"性能信号"其实是扰动噪声，不是真实能力差异。

### 3.4 "63% 排名变化"的精确计算方法

论文原话（line 546-552）："we quantify this effect by computing model rankings for the six open-weight models on each task before and after applying a perturbation. We measure their agreement using Spearman rank correlation, averaged across tasks and reported separately for zero-shot and few-shot settings."

即：对 6 个开源模型在每个任务上先排序一次（baseline），施加一个扰动后再排序一次，用 **Spearman 等级相关系数**量化两次排序的一致性。"introducing even a single perturbation changes the relative ranking of the six open-weight models in **63% of cases**"——指所有 (任务×扰动) 组合中，排序发生显著不一致的比例达 63%。具体地，引号/换行等 padding 扰动导致的相关性最低（zero-shot Spearman 0.63–0.67），单纯空格/拆词扰动相关性仍有 0.87–0.91。

### 3.5 "12% 下降"的含义

指在所有 (benchmark×扰动) 组合中，**最大观测到的平均绝对准确率下降达 12 个百分点**（abstract）；word-level 扰动（typos、spacing changes）一致地带来数个百分点的下降，且**即使最前沿的模型也无法幸免**。

### 3.6 与"跨 prompt 适配"的关联

Brittlebench 提供了理论框架（方差分解）来证明：单次评估结果中**有近一半的"信号"是 prompt 扰动造成的噪声**，必须做多扰动评估才能分离真实能力。

## 4. POSIX —— 不看下游性能，直接量化模型对 prompt 变化的"内在敏感度"

**论文**：Chatterjee, Renduchintala, Bhatia & Chakraborty，IIT Delhi + Adobe，2024（[arXiv 2410.02185](https://arxiv.org/abs/2410.02185)，[代码](https://github.com/kowndinya-renduchintala/POSIX)）

### 4.1 核心定义：Intent-aligned prompt set

定义 3.2：一组 prompt $X=\{x_i\}_{i=1}^N$，其中任意两个 $x_i,x_j$ 措辞/模板/拼写各不相同，但底层目标/意图/含义相同。

### 4.2 POSIX 公式

对单个 prompt set $X$（$|X|=N$），先让模型 $M$ 对每个 prompt $x_i$ 生成响应 $y_i$，再计算 per-set 敏感度：

$$
\psi_{M,X}=\frac{1}{N(N-1)}\sum_{i=1}^{N}\sum_{j=1}^{N}\frac{1}{L_{y_j}}\left|\log\frac{P_M(y_j|x_i)}{P_M(y_j|x_j)}\right|
$$

- $L_{y_j}$：响应 $y_j$ 的 token 数（长度归一化）
- $P_M(y_j|x_i)$：在 prompt $x_i$ 下，模型生成 $y_j$ 的概率
- $|\log(\text{ratio})|$：把概率比转为对数尺度 + 取绝对值，对不同 prompt set/不同模型概率尺度归一

整体 POSIX 指数（Definition 3.4）：在 $M$ 个不同 intent-aligned prompt set 上取 $\psi$ 的均值：

$$
\text{POSIX}_{D,M}=\frac{1}{M}\sum_{i=1}^{M}\psi_{M,X_i}
$$

### 4.3 关键发现

$\psi$ 与四个因素正相关：响应多样性（Response Diversity）、响应分布熵（Response Distribution Entropy）、语义一致性（Semantic Coherence）、置信度方差（Variance in Confidence）——所以 POSIX 是一个比"exact match 波动"更细粒度的指标。实证发现：**参数增大或指令微调不必然降低 prompt 敏感度**；**仅 1 个 few-shot 示例即可显著降低 POSIX**；MCQ 类任务中 prompt template 变更最敏感，开放生成中 paraphrasing 最敏感。

### 4.4 与背景动机的关系

POSIX 提供了一个**模型无关、无需 ground truth** 的敏感度量，可在 prompt/模型适配前，先快速判断"这个模型/任务组合到底需不需要适配"，作为筛选信号。

## 5. Multi-Prompt Eval —— 用统计证明"单 prompt 分数是有偏估计"

**论文**：Mizrahi et al.，Hebrew University + U. Haifa，*State of What Art?*，TACL 2024（[arXiv 2401.00595](https://arxiv.org/abs/2401.00595)，[代码](https://github.com/SLAB-NLP/Multi-Prompt-LLM-Evaluation)）

目前规模最大的相关实证：6.5M 评估实例、20 个 LLM、3 个 benchmark、39 个任务、5K instruction paraphrase（用三种自动改写方法+人工校验构造，改写质量：LMentry 90% 正确，BBH 84% 正确）。

### 5.1 指标族

设 $M$ 为 LLM，$T$ 为任务，$I_T$ 为该任务全部 instruction 模板集合，$\epsilon(M,T,i)\in[0,1]$ 为 $M$ 在模板 $i$ 上的标准指标（accuracy/F1）：

| 指标 | 公式 | 用途 |
|---|---|---|
| **MaxP** | $\max_{i\in I_T}\epsilon(M,T,i)$ | 下游开发者：给定模型找最优 prompt |
| **AvgP** | $\frac{1}{|I_T|}\sum_{i\in I_T}\epsilon(M,T,i)$ | LLM 开发者：评估平均意义下的鲁棒性 |
| **Sat**（Saturation） | $1-(\text{MaxP}-\text{AvgP})$ | 最优 prompt 与平均 prompt 的接近度（高=鲁棒） |
| **CPS** | $\text{Sat}\times\text{MaxP}$ | 同时考虑最优与平均 |

### 5.2 排序稳定性统计

**Kendall's $W\in[0,1]$**：跨 $m$ 个模板（judge）对 $n$ 个 LLM（object）排序的组内一致性系数（$W=1$ 完全一致，$W=0$ 完全无关）：

$$
W=\frac{12\sum_{i=1}^{n}(R_i-\bar{R})^2}{m^2(n^3-n)},\qquad R_i=\sum_{j=1}^{m}r_{ij}
$$

实测：许多任务的 $W$ 值很小——单一模板排序不可靠。Friedman 检验显示 25 个任务中有 **21 个显著**因 prompt 变化得到不同排序。

**Kendall's $\tau\in[-1,1]$**：两个具体模板给出排序的配对一致性。**15/25 个任务**中存在 $\tau<0$ 的模板对——意味着仅换 2 个模板就能给出完全反向的排序。

### 5.3 估计程序

**估算 AvgP**：对每个 task sample，从 paraphrase 池中随机采样一个模板评估模型，重复 20 次取平均。**估算 MaxP**：贪心搜索——先用 10 个 instance 评估全部 paraphrase，筛出 top-100，再用 10 个 instance 筛 top-10，最后在剩余 instance 上选最优。

### 5.4 关键发现

"Average performance is lower than that observed in the original benchmark instructions. In 72.5% of the cases, the performance of the original instructions was higher than the estimated average across all paraphrases. In the davinci model, the original prompts added on average 21 more accuracy points."——即**原始 prompt 比"多 prompt 平均"高 21 个点**，标准 benchmark 报告的单点分数系统性高估真实能力。

### 5.5 与背景动机的关系

给出了最直接的统计论据：单一 prompt 评估报告的分数既不是无偏点估计，也不是一致排序器。任何 prompt-adaptive/model-adaptive 方法必须在多 prompt 上做报告，否则结论不成立。

## 6. AgentBench 与 AgentBoard —— 把同样的不稳定性搬到多步 Agent 层面

### 6.1 AgentBench

**论文**：Liu et al.，THUDM+OSU+Berkeley，ICLR 2024（[arXiv 2308.03688](https://arxiv.org/abs/2308.03688)，[代码](https://github.com/THUDM/AgentBench)）

**8 个真实交互环境**分三类：**Code-grounded**（OS：真实 Ubuntu Docker + bash shell，success rate；DB：真实 SQL 接口多表多查询，SR；KG：知识图谱问答，answer F1）、**Game-grounded**（DCG：Aquawar 卡牌对战，win rate；LTP：海龟汤，game progress；HH/ALFWorld：家庭具身任务，SR）、**Web-grounded**（Webshop：模拟电商，SR；Mind2Web：真实网页，Step SR）。评估对象：27 个 LLM，dev/test 269/1091 个任务，每题 5-50 轮交互，统一用 CoT prompting 作为范式，API-centric 工具 + Docker 封装 + worker 隔离。

主要发现：商用顶级模型 agent 能力强，但与开源差距显著；失败主因是长期推理/决策/指令跟随能力弱。

### 6.2 AgentBoard

**论文**：Ma et al.，HKU+Tsinghua+SJTU+Westlake+HKUST，NeurIPS 2024（[arXiv 2401.13178](https://arxiv.org/abs/2401.13178)，[代码](https://github.com/hkust-nlp/AgentBoard)）

**4 大场景、9 个任务、1013 个环境**，全部要求多轮+部分可观察：**Embodied**（ALFWorld 家庭具身；ScienceWorld 科学常识，重新标注更密集的 subgoal；BabyAI 20×20 网格导航，改造为文本观察/动作）、**Game**（Jericho 文字冒险，改写目标使其 15 个 subgoal 内可完成；PDDL 4 个规划游戏——Gripper/Barman/Blocksworld/Tyreworld，转为文本观察）、**Web**（WebShop 电商，改进错误反馈；WebArena 真实网页，改写 URL+内容匹配）、**Tool**（Tool-Query：Weather/Movie/Academia 数据库查询，要求必须走工具调用轨迹；Tool-Operation：Todo list + Google Sheet 操作）。

**核心创新**：success rate 无法区分"接近完成"与"刚开始就失败"。AgentBoard 引入 **fine-grained progress rate** $r_t\in[0,1]$：**subgoal-based**（人工手动/重新标注每个任务的 subgoal 序列，每完成一个 subgoal 进度按比例增加，如 ALFWorld"把干净的蛋放进微波炉"任务中"打开冰箱"一步进度 0.00→0.25）或 **matching-based**（当前状态与目标状态的相似度，用于 PDDL/WebShop/Sheet）。人类评估验证 Pearson $\rho$ 与 Fleiss's kappa 双高，证明 progress rate 标注可靠。配套 6 类细粒度分析（fine-grained progress rate 跟踪、grounding accuracy、难/易样本分解、长程交互分析、子技能维度分解、trajectory 可视化）+ Wandb 实时可视化面板。

### 6.3 两者的定位差异

AgentBench 提供首个多环境 agent benchmark，证明 agent 能力在不同环境间不可直接迁移；AgentBoard 把评估从"二元成功/失败"推进到"连续进步率"，证明 agent 能力是连续光谱而非二态。两者共同支持：**"环境"对 agent 来说就是它的"prompt"**——跨环境评估的不稳定性和跨 prompt 评估的不稳定性，是同一类问题在不同层面的体现。

## 7. 综合叙事线：为什么"需要适配"不是工程洁癖而是评估理论的硬约束

把 7 项工作串成一条论证链：

1. **PromptRobust**：最朴素的对抗扰动就能让单点性能下降 20–33%，说明 prompt 表面形式不可忽略
2. **PromptBench**：把 ① 工程化为可扩展库，说明这一现象系统性存在于多模型多任务
3. **Multi-Prompt Eval**：把评估从"单点"推到"分布"，发现单 prompt 比多 prompt 平均高估 ~21 个点，说明单点评估本身就是有偏估计
4. **POSIX**：超越外部性能度量，直接用对数似然变化定义 prompt 敏感度，说明"敏感性"是模型的内禀属性、可独立于任务测量
5. **Brittlebench**：用方差分解证明性能方差最多 ~50% 来自 prompt 扰动，63% 排名变化说明跨模型比较在 prompt 变化下不可靠
6. **AgentBench / AgentBoard**：把同样的不稳定性在 agent 层面放大——同一 LLM 在 8 个真实环境上行为极不一致，说明"环境"就是 agent 任务的"prompt"

**结论**：跨模型/跨 prompt/跨环境的适配，不是工程便利，而是**评估理论本身的硬约束**——忽略这一约束得出的任何单点评测结论都不可信。这正是 [[3. Adaptive prompt for diff LLM]] 里"model drifting 普遍且严重"这一现象在评测方法论层面的根源解释。
