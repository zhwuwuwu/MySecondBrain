# Agent 场景 Prompt 优化深度解读：AutoPDL 与 RePrompt

> 范围：[[3. Adaptive prompt for diff LLM]] 类别三"Agent/Tool-use 场景特化"的两篇论文（AutoPDL / RePrompt）。
> 主线问题：单模型自动优化（类别一，见 [[2. Agent Prompt Auto Opt]]）针对的是"改措辞"，这两篇针对的是 agent 多步场景下更根本的问题——**该用什么推理范式**（CoT/ReAct/ReWOO？）以及**没有 final checker 时怎么优化**。

---

## 1. AutoPDL —— 把"选推理范式"本身当 AutoML 问题

**论文**：Spiess, Vaziri, Mandel & Hirzel，*AutoPDL: Automatic Prompt Optimization for LLM Agents*，UC Davis + IBM Research，AutoML 2025 Methods Track（[arXiv 2504.04365](https://arxiv.org/abs/2504.04365)，代码：[IBM/prompt-declaration-language](https://github.com/IBM/prompt-declaration-language)）

### 1.1 搜索空间：不只是选 pattern，是笛卡尔积

常见误解是"AutoPDL 只在 {Zero-Shot, CoT, ReAct, ReWOO} 4 个选项里挑一个"。实际搜索空间是多个维度的笛卡尔积（§8.4）：

| 维度 | 取值 | 备注 |
|---|---|---|
| Pattern $A$ | {Zero-Shot, CoT, ReWOO, ReAct} | MBPP+ 排除 ReWOO（非 reactive 任务） |
| Few-shot 数 $n$ | {0, 3, 5} | 0 即退化为 Zero-Shot，强制包含 |
| System prompt | {Granite Tools, LLaMa 3, Granite LLaMa} | 仅 ReAct 时生效 |
| Few-shot 样本 | 从训练集有放回采样 | 具体样本内容也是搜索对象 |

每个候选配置是 $c_i=\langle A,n,d_{\text{train}},\text{instr}\rangle$。搜索空间用 YAML 声明式描述（Figure 2）：

```yaml
variables:
  prompt_pattern: [cot, react, rewoo]
  num_demonstrations: [0, 3, 5]
  system_prompt: [granite_tools, llama3, granite_llama]
initial_test_set_size: 16
max_test_set_size: 1000
num_candidates: 100
parallelism: 5
```

4 个 pattern 库的实现差异：**Zero-Shot** 单次调用直接 $(x\to y)$；**CoT** 少样本+推理链 $(x,[y,\text{tho}]_k)\to\text{tho}\to y$；**ReWOO** 推理与执行分离——先批量生成 thought+action，**执行所有工具调用**收集 observation，再生成最终答案（工具调用可并行，天然更快）；**ReAct** 是 TAO（thought/action/observation）循环，带特殊 `Finish` 动作跳出循环。

### 1.2 Successive Halving：怎么把搜索预算花在最有希望的候选上

论文 §8.3 Algorithm 1 给出完整伪代码：

```
Require: 候选集 C（初始 100 个）, D_valid, v_min=16, v_max=1000
v ← v_min
while |C| > 1:
    d_valid ← D_valid 的前 v 个样本
    for c_i in C: 计算 loss ℓ_i ← L(c_i, d_valid)
    C ← loss 最小的 ⌊|C|/2⌋ 个候选
    v ← min(v_max, 2·v)
return C 中 loss 最小的候选
```

**被减半的是候选数**（100→50→25→...→1），**被翻倍的是验证子集大小**（16→32→64→128→256→512→1000）——用少量样本快速淘汰明显差的候选，把评测预算留给少数幸存者在更大验证集上精确比较。搜索空间本身（100 个候选）在启动前一次性采样好，之后不再变化。实验配置：3 次重复、greedy decoding。

### 1.3 PDL：输出不是自然语言 prompt，是可执行程序

PDL（Prompt Declaration Language，IBM Research，独立发表于 [arXiv 2410.19135](https://arxiv.org/abs/2410.19135)）是 YAML 声明式语言：LLM-agnostic（底层走 LiteLLM）、支持 Jinja 表达式插值、`def`/`call`/`if-then`/`include` 控制结构、JSON schema + 约束解码。AutoPDL 做的是**source-to-source optimization**——输入输出都是 PDL 程序，人可读可改，不是黑盒调完的一段文本。一个 CoT 2-shot 的优化后配置示例（GSM8K，Figure A1，节选）：

```yaml
defs:
  prompt_pattern: cot
  num_demonstrations: 2
  demonstrations:
    data:
    - question: |
        Tricia is a third of Amilia's age and Amilia is a quarter of
        Yorick's age...
      reasoning: |-
        Rupert is younger than Vincent by 2 years, so he is 22 - 2 = 20...
      answer: '5'
  instruction: "Answer the questions to the best of your abilities."
text:
- include: CoT.pdl
- call: {args: {examples: ..., question: ..., model: ...}}
```

渲染后送入 LLM 的实际文本会把 `defs` 里的模板变量展开成一段完整的 few-shot CoT prompt。

### 1.4 核心证据："No one size fits all"——最优 pattern 随模型和任务系统性变化

3 任务（FEVER/GSM8K/MBPP+）× 7 模型（Granite 3.1-8B/13B-V2/20B-Code/34B-Code、LLaMA 3.1-8B/3.2-3B/3.3-70B）完整跑一遍 successive halving，平均提升 **9.21 ± 15.46 pp**，最高 **+67.5pp**（Granite 13B V2 on FEVER：6.5%→74.0%，选中 ReWOO 3-shot）。

**同任务不同模型选中不同 pattern**：FEVER 上 4/7 模型选 ReWOO、3/7 选 CoT，无一选 Zero-Shot；GSM8K 上 4/7 选 CoT、3/7 选 Zero-Shot，无一选 ReAct/ReWOO；MBPP+ 上 3/7 选 ReAct、4/7 选 Zero-Shot（ReWOO 排除在外）。

**同模型不同任务也选中不同 pattern**（以 3 个 LLaMA 为例）：

- LLaMA 3.1-8B：FEVER→CoT 3-shot，GSM8K→CoT 5-shot，MBPP+→ReAct 5-shot
- LLaMA 3.2-3B：FEVER→ReWOO 5-shot，GSM8K→CoT 3-shot，MBPP+→Zero-Shot
- LLaMA 3.3-70B：FEVER→ReWOO 3-shot，GSM8K→CoT 3-shot，MBPP+→Zero-Shot

每一行的 3 个任务几乎都选中不同 pattern——这是"同一个 agent 功能在不同模型上可能需要不同**范式**而非仅不同措辞"的最直接实证。

跨数据集迁移（在 GSM8K 上优化出的配置直接搬到 GSM-Hard）效果打折但仍普遍正向（如 LLaMA 3.3-70B 47.3%→53.8%，+6.5pp）；跨模型迁移（在 LLaMA 3.1-70B 上优化出的配置直接搬到 GPT-4o-mini）在多数据集上仍有正向增益（GSM8K 77.8%→90.9%，FEVER 83.7%→87.7%），说明"pattern 选择"本身有一定的跨模型可迁移性，但不如"针对目标模型重新搜索"稳定（MBPP+ 上迁移增益为 0）。

### 1.5 定位

核心贡献：(1) 首次联合搜索 pattern + prompt 内容而非只调措辞；(2) 实证"no one size fits all"；(3) source-to-source，输出可读可改。局限：搜索空间目前只覆盖 4 个经典 pattern，不包含更新的 agent 范式（如 Reflexion、Tree-of-Thought）；successive halving 需要较大验证集（最多 1000 样本）才能可靠区分候选。

## 2. RePrompt —— 没有 final checker 时怎么做自动 prompt engineering

**论文**：Chen, Koenig & Dilkina，*RePrompt: Planning by Automatic Prompt Engineering for LLM Agents*，USC（NSF 2112533 资助），2024（[arXiv 2406.11132](https://arxiv.org/abs/2406.11132)）

### 2.1 问题定位

已有 APE 方法依赖 **final checker**（能对最终输出打一个分数），但 agent 场景里"中间反馈易得、最终评估昂贵/不准/甚至没有"（论文原话："previous works in APE rely on a final checker to evaluate the performance of the given prompt — a requirement that is hard to meet in the case of LLM agents, where intermediate feedback is easier to obtain, and the final evaluation could be expensive, inaccurate, or even missing."）。RePrompt 的贡献是设计一套不需要 ground-truth 最终分数、只靠**中间反馈**驱动的 prompt 优化循环。

### 2.2 "中间反馈"到底是什么——不是标量 reward，是完整对话历史

三个评测任务的 feedback 来源完全不同（§4.1）：

| 任务 | Feedback 来源 | 特点 |
|---|---|---|
| PDDL Generation | PDDL 语法检查器 + LLM-as-judge | 精确但昂贵 |
| TravelPlanner | ReAct/Reflexion 工具观察 + 预算查询 | 廉价但不精确 |
| Meeting Planning | DeepSeek-R1 自己的 thinking 部分 | 内省式 self-feedback，不依赖外部工具 |

与常见的"step-level reward"不同——RePrompt 收集的是**完整对话轨迹**（Thought/Action/Observation 序列），不是每步一个标量分数。例如 TravelPlanner 上一条 feedback 可能是"The flight is taking \$2,500, which is too expensive"这样的自然语言观察。

### 2.3 三组件架构 + 训练循环

**Actor**：用当前 prompt 跑 agent，收集完整 chat history。
**Summarizer（相当于"Loss"）**：LLM 把 chat history 提炼成一句话"focus point"——三种输出模式：(a) 总结失败的主因；(b) 把某次有用的想法归纳成通用原则；(c) 判定为 case-by-case 错误、无通用规律。
**Prompt Optimizer**：LLM 根据 focus point，只修改 prompt 里的 **step-by-step 指令部分**（不碰 scenario-specific 内容），遵循两条规则："改结构不改具体场景内容"、"改'这类问题该注意什么'"，并内置 3 个 hardcoded 常见修改方案（如"若发现细节遗漏→逐句检查"）。

```
function TRAIN():
    Prompt ← Initial Prompt
    for (batch, x) in Dataloader:
        Response ← ACT(Prompt, x)
        Loss ← SUMMARIZE(Response, x, Prompt)     # LLM, 非数值
        Prompt ← OPTIMIZER(Loss, Prompt)           # LLM, 非数值
    return Prompt
```

关键：这里的"loss"和"optimizer"都是 LLM 调用，不是数值计算——这是它与 ProTeGi（详见 [[2. Agent Prompt Auto Opt]]）的本质区别：

| 维度 | ProTeGi | RePrompt |
|---|---|---|
| 反馈信号 | 数值化 task loss | LLM 生成的文本 focus point |
| 编辑粒度 | 句子/短语 | 仅 step-by-step 指令 |
| 需要 ground truth | 是 | **不需要** |
| 适用场景 | 单轮 QA | 多轮 agent |

RePrompt 自述（Related Works）："can be seen as a generalization of the current methods to reasoning domains. Importantly, in our settings, we do not require ground-truth feedback."

### 2.4 结果

评测设置：GPT-4-turbo-1106-preview（PDDL + TravelPlanner）、DeepSeek-R1（Meeting Planning），temperature=0，训练 batch 10 样本，best-of-3 trials。

**TravelPlanner（论文最强结果，Table 2）**：Reflexion baseline Commonsense (Macro) pass rate 56.39%、Final pass 2.78%；PromptAgent 56.39%/2.11%；**RePrompt 5-epoch** 达到 Commonsense **80.00%**（+24pp）、Final pass **3.89%**、Delivery rate 99.44%。5 epoch 后模型自动学到"合理城市路线"这类 commonsense 约束并写入了 prompt。训练样本数消融（固定 样本数×epoch=50）：1 样本 Final pass 1.22%，10 样本 **3.89%**（sweet spot），25 样本反而降到 2.00%——过多样本单 epoch 学习不充分。

**PDDL Generation（Table 1）**：Household 域（22 actions）上 Guan 2023 baseline 有 19 个动作出错、52 处总错误；RePrompt 降到 12 个动作出错、23 处总错误，且**新 prompt 引入的错误是原错误的子集**（不引入新错误类型）。

**Meeting Planning（Table 4）**：0-shot DeepSeek-R1 21.00% → 5-epoch RePrompt **26.00%**。

### 2.5 局限（论文自述）

训练分布与测试分布差异会明显伤害性能；优化器可能建议不存在的工具；feedback generator 本身可能产生误导信号；论文原话——"if the LLM agents are proposed for very general domains that need completely different procedures in different scenarios, our proposed method will not work at all"（即目标场景需要有一定的结构相似性，方法才有效）。错误模式方面：Optimizer 有时输出带占位符的模板（处理：再用 LLM 替换占位符）、偶尔误改格式（如把"Preconditions"错改成"precondition"，靠 syntax checker 检测后重跑，失败率 <10%）。

## 3. 两篇对跨模型适配问题的共同启示

| 维度 | AutoPDL | RePrompt |
|---|---|---|
| 问题定位 | 一次性架构+prompt 联合搜索 | 在线 prompt 微调（无 final checker） |
| 搜索算法 | Successive Halving | LLM-as-gradient（多轮迭代） |
| 反馈来源 | 验证集 task accuracy | 对话历史/中间 feedback |
| 优化对象 | Pattern + few-shot + system prompt + 样本 | 仅 step-by-step 指令 |
| 需要 ground truth | 是（验证集） | 否 |
| 输出形式 | 完整 PDL 程序 | 修改后的 prompt 文本 |

两者共同指向一个在各自论文之外都成立的结论：**agent 多步场景的"跨模型适配"不能只停留在"改写同一份 prompt 的措辞"层面**——AutoPDL 证明不同模型甚至需要不同的**推理范式**（ReAct vs CoT vs ReWOO），RePrompt 证明即使没有最终分数，仅靠中间轨迹也能学到可迁移的 commonsense 约束。这意味着类别二（见 [[3.1. Cross-Model Prompt Transfer 深度解读]]）里的 PromptBridge/MAPO 等方法如果直接套用到多步 agent 场景，可能只解决了"措辞层"的漂移，而漏掉了"范式层"的漂移——这正是 [[3. Adaptive prompt for diff LLM]] 里提到的"研究缺口"之一：尚未有工作系统研究"同一 agent 功能 × 多模型 × 需要不同 prompting 范式"的联合适配。
