# 跨模型 Prompt 迁移与适配：四种范式深度解读

> 范围：[[3. Adaptive prompt for diff LLM]] 类别二"跨模型 Prompt 差异/迁移/适配"的 4 篇核心论文（PromptBridge / MAPO / Zero-Shot Continuous Prompt Transfer / Transfer-Prompting）+ DSPy 编译范式的精确机制。
> 主线问题：它们各自说的"跨模型"到底是同一件事吗？——答案是：**不是**。四篇论文对应四种几乎不重叠的技术路径，混着读会互相误导。

---

## 0. 先厘清：4 种"跨模型"完全不是一回事

读完全部原文后最重要的发现是——这四篇论文的"迁移轴"根本不同：

| 论文 | Prompt 类型 | 迁移的是什么 | 是否训练 | 是否真的"跨模型" |
|---|---|---|---|---|
| **PromptBridge** | 离散文本 | 同任务，从模型 A 的最优 prompt 推出模型 B 的最优 prompt | training-free（仅推理期调用 LLM） | ✅ 是，且是最直接命中 |
| **MAPO** | 离散文本 | 同任务，但要为**每个**目标模型**单独训练**一个 prompt 改写器 | 需要 SFT+RL 训练 | ⚠️ 是"model-adaptive"，但不是"迁移"——没有从 A 推出 B，是每个模型各自算一遍 |
| **Zero-Shot Continuous Prompt Transfer** | 连续 embedding（soft prompt） | 把源模型的 soft prompt 通过相对表征迁到结构/维度都可能不同的目标模型 | 源端 prompt 需训练，目标端只做搜索、不训练模型 | ✅ 是，且是"迁移"语义最强的一篇（跨架构） |
| **Transfer-Prompting** | 离散文本 | 同一模型（scorer LLM 不变），从相关领域任务迁到目标任务 | 不训练模型，仅搜索 prompt 文本 | ❌ 实际是**跨任务**，"25 个模型"只说明方法鲁棒，不是真的处理了模型差异 |

带着这张表读下面的深度拆解，才不会把"training-free 文本迁移""per-model 训练""连续向量迁移""跨任务优化"四个不同的问题混成一个。

## 1. PromptBridge —— 唯一真正做到"training-free 跨模型 prompt 翻译"

**论文**：Wang et al., *PromptBridge: Cross-Model Prompt Transfer for Large Language Models*，UC Santa Cruz + Accenture，2025（[arXiv 2512.01420](https://arxiv.org/abs/2512.01420)，[代码](https://github.com/supergirl-os/PromptBridge)）

### 1.1 MAP-RPE：先给每个模型各自跑出"专属最优 prompt"

MAP-RPE = **Model-Adaptive Reflective Prompt Evolution**（模型自适应反思式提示进化）。它不是迁移算法，是**校准阶段**用来给单个模型 $M$ 在单个任务 $S_i$ 上进化出专属最优 prompt $p^*_{M,S_i}$ 的工具——概念上接近 GEPA/AlphaEvolve 的"LLM 反思 + 进化"，但引入了显式量化指标做 metric-driven 选择而非纯文本反馈：

- **vs. GEPA**：GEPA 依赖纯文本反馈 + Pareto-aware 选择；MAP-RPE 引入 performance + behavioral + task-specific 三类量化分数
- **vs. AlphaEvolve**：AlphaEvolve 在代码 mutation 空间进化；MAP-RPE 进化的是 prompt template 本身，不动模型参数、不用梯度

```
Input:  任务 S_i, 目标模型 M, 存档 𝓑（K=3 个 island）,
        反思模型 = GPT-5, 全局迭代 G=20, 局部步 L=10
p₀ ← 种子 prompt；对每个校准样本跑一遍 M，存入 𝓑

for g = 1..G:
    for 每个校准样本 x_j:
        用当前 best 模板跑 M，得响应 r
        (a, b) ← 𝓔(x_j, r)          # a = 任务分, b = behavior 分
        若 a = Solved: 跳过
        𝓑 ← 𝓑 ∪ ⟨p, (a,b)⟩
        for l = 1..L:
            从 island 选 parent + inspiration
            p_child ← GPT-5(任务描述, 上轮模板, 评估反馈)   # LLM 改写
            跑 M(p_child(x_j))，记录 𝓔
            𝓑 ← 𝓑 ∪ {p_child}；满足条件则 island 间迁移
p* ← argmax_{p∈𝓑}  λ·Perf(p) + (1−λ)·Behavior(p)，λ=0.8
```

代码生成任务的 Behavior 分 4 项加权：语法合法性 0.35、入口函数定义 0.35、无风险模式 0.20（`exec`/`eval`/文件系统调用等）、无干扰模式 0.10。校准题数 $n=20$，存档容量 1000，island 间每 50 步迁移一次（迁移率 0.1）。

**关键**：MAP-RPE 只负责"单模型内找最优 prompt"，不解决跨模型问题——它是后面 Mapping 阶段的**原料生成器**。

### 1.2 Calibration：用"同任务、不同模型"的 prompt 对做训练素材

对 $m$ 个对齐任务（来自 synthetic-code-generations + CodeContests 训练集），每个任务上**分别**对源模型 $M_s$ 和目标模型 $M_t$ 独立跑一遍 MAP-RPE：

$$
p^*_{M_s,S_i}=\text{MAP-RPE}(M_s, S_i), \qquad p^*_{M_t,S_i}=\text{MAP-RPE}(M_t, S_i)
$$

得到 $m$ 对"同任务、不同模型"的最优 prompt。这些 alignment 任务与最终评测的 unseen 任务（HumanEval/MBPP/APPS/xCodeEval/CodeContests/SWE-Bench Verified/Terminal-Bench/TravelPlanner）完全不重叠——这保证了后面的"迁移"是真正的 zero-shot，而不是在测试任务上直接调参。

### 1.3 核心机制：Mapping 不是参数，是一段自然语言摘要

这是整篇论文最容易被误解的地方——**PromptBridge 没有训练任何神经网络参数**，跨模型映射由两个 LLM 角色接力完成：

**① Mapping Extractor**（GPT-5）：把 $m$ 对 `(source prompt, target prompt, 数据集信息)` 整段喂进去，system prompt 是 "You are a helpful assistant that summarizes the difference of prompts."，要求输出一段**自然语言摘要**——"从 source prompt 改成 target prompt 时的共同结构/风格/推理差异"。这段摘要本质上就是学到的映射：

$$
\mathcal{T}_{M_s\to M_t;S}: p^*_{M_s,S_i}\mapsto p^*_{M_t,S_i}\quad\text{for } S_i\in S
$$

**② Adapter**（也是 GPT-5）：测试时对**未见过**的新任务 $T_j$，把新的 source prompt + 上面那段 transfer-effects summary 拼进模板，一次调用直接生成 target prompt：

$$
\hat{p}_{M_t,T_j}=\mathcal{T}_{M_s\to M_t;S}(p_{M_s,T_j})\approx p^*_{M_t,T_j}
$$

Adapter 的实际 prompt 模板（节选，代码任务版本）：

```
Your task is to apply the transfer effects from the source prompt to
generate a new target prompt... Begin from the Original Prompt below.
## Original Prompt: {Source Prompt}
## Transfer Effects Summary: {summary}
## Task: Apply the above transfer effects summary to the Original Prompt
designed for {source_model}. Generate a new prompt adapted for
{target_model}...
Optimized Prompt:
```

SWE-Bench / Terminal-Bench / TravelPlanner 各有专门变体，但结构一致。

**为什么是 training-free**：论文原话——"extracts model-level differences through linguistic summarization instead of relying on heavy gradient-based signals"。整条 pipeline 没有梯度更新、没有可学习的 head、也没有向量检索库（消融里对比的 one-shot/few-shot ICL 只是把 pair 塞进 prompt，PromptBridge 显著优于它们，见下表）。所谓"学习"，指的是 GPT-5 在 in-context 里"看 pair→写摘要"，而不是 SGD。

### 1.4 结果：从"迁移几乎失效"到"接近甚至超过目标模型自己最优"

代码生成（源=GPT-4o，Pass@1）：

| Target | Method | HumanEval | MBPP | APPS | xCodeEval | CodeContests |
|---|---|---:|---:|---:|---:|---:|
| o3 | Direct Transfer | 92.27 | 77.92 | 32.67 | 66.04 | 48.61 |
| o3 | **PromptBridge** | **97.15** | **80.44** | **36.44** | **74.84** | **56.36** |
| Llama-3.1-70B | Direct Transfer | 68.70 | 65.57 | 10.00 | 21.38 | 20.20 |
| Llama-3.1-70B | **PromptBridge** | **79.88** | **73.64** | **11.11** | **24.53** | **23.84** |

APPS/xCodeEval/CodeContests 上相对 Direct Transfer 的相对增益：o3 +11.5%/+13.3%/+15.9%；o4-mini +0.6%/+7.9%/**+46.5%**；Llama-3.1-70B +11.1%/+14.7%/+18.0%。

SWE-Bench Verified（源=o4-mini，默认 prompt 38.60%，MAP-RPE 优化后 42.20%）：o3 目标上 Direct Transfer 33.40% → **PromptBridge 46.00%**（+27.4% 相对增益）；Llama-3.1-70B 目标上 7.60% → **8.80%**（+15.8%）。Terminal-Bench 上（源=GPT-4o）o3 目标 +39.4%、o4-mini 目标 +10.5%；附录里源=o3 时 GPT-4o 目标 +25%、Llama-3.1-70B 目标 +40%。

Ablation（Table 5，o3 目标）：One-shot ICL 89.63 / Few-shot ICL 87.40 / **PromptBridge 97.15**（HumanEval）——证明"摘要+改写"显著优于"把 pair 直接塞进 prompt 当 few-shot"，即映射的价值在于"提炼共性"而非"记住个例"。

### 1.5 Multi-agent（MapCoder）：每个 sub-agent 独立走一遍完整流程

多智能体场景下漂移分两种：**全局漂移**（所有 agent 同时切模型）和**局部漂移**（只切某一个 agent，如只换 Debugging agent）。PromptBridge 没有特殊化处理——对 MapCoder 的 Retrieval/Planning/Coding/Debugging 4 个 agent，若全部从 GPT-4o 切到目标模型，就分别学 4 条独立的 transfer mapping；若只切 Coding agent，就只对 Coding agent 的 prompt 学 1 条 mapping，其他 3 个不动。局部漂移时 PromptBridge 不总是全面最优，但在 **Debugging Agent** 上稳定最佳（与 MapCoder 原论文"Debugging agent 是性能关键"的观察一致）。TravelPlanner 的两阶段（ReAct Agent + Planner Agent）上，局部只切 Planner 时 PromptBridge 在 Hard-Constraint pass rate 上从 23.33% 提到 **30.00%**。

### 1.6 形式化：Model Drifting 与 Transfer Gap

$$
\Delta(M_s\to M_t,T)=A(M_t,T,p^*_{M_s,T})-A(M_t,T,p^*_{M_t,T})\;(\le 0)
$$

即"直接把源最优 prompt 套到目标模型"比"目标模型自己的最优 prompt"少多少，绝对值越大漂移越严重。论文用这个指标证明漂移**普遍存在**（甚至同 family 不同 scale 之间也有 50–70% 的相对损失），并在 embedding 空间里计算 $v_t=e(p^*_{target,t})-e(p^*_{source,t})$ 的 cosine similarity across tasks，论证"漂移模式跨任务相对稳定 ⇒ 可学习"——这正是 Mapping Extractor 能 work 的前提假设。相对增益的报告口径：

$$
\text{Relative Gain}=\frac{\text{Accuracy}_{\text{PromptBridge}}-\text{Accuracy}_{\text{Direct}}}{\text{Accuracy}_{\text{Direct}}}\times100\%
$$

### 1.7 局限（论文自述）

仅在 GPT-4o/o3/o4-mini/Llama/Qwen3/Gemma3 验证，未覆盖 Mistral、DeepSeek、SFT/DPO/GRPO 对齐模型；主要是代码生成场景，非代码/多模态/长上下文未深入；重度依赖 GPT-5 API 调用（Mapping Extractor + Adapter + MAP-RPE 反思器都要调 GPT-5），没有量化这部分 token 成本；评估用 Pass@1 + temperature=0，未充分覆盖多次试验的稳定性。

## 2. MAPO —— "Model-Adaptive"但不是"迁移"：per-model 训练一个改写器

**论文**：Chen et al., *MAPO: Boosting Large Language Model Performance with Model-Adaptive Prompt Optimization*，Fudan/SMU/Tencent/Ant Group，2024（[arXiv 2407.04118](https://arxiv.org/abs/2407.04118)）

MAPO 论证的命题和 PromptBridge 不同——它不关心"从 A 推出 B"，而是主张：好 prompt 必须同时 task-adaptive **和** model-adaptive，所以要**为每个目标模型单独训练**一个 prompt 改写器。整条 pipeline 分三段。

### 2.1 Oracle 生成候选 + 选出最优（Warm-up 数据集构建，§3.1）

- **Oracle** = GPT-3.5，对每个原始 prompt $P$ 生成 **1000 个语义保持的改写候选**（指令："Please rewrite the given text 'original prompt' while keeping the semantic meaning unchanged."）
- 用**目标 LLM**（BLOOM-7B / GPT-J-6B / LLaMA-7B）逐个跑这 1000 个候选，按任务类型用 F1（QA）/ Accuracy（分类）/ ROUGE-L（生成）与 ground-truth 比对
- $P_o=\arg\max_{\text{候选}} \text{metric}$，选出的 $P_o$ 与原始 $P$ 组成 warm-up 对 $\{(P,P_o)\}$

数据规模（P3 benchmark 9 个数据集，QA/分类/生成各 3 个）：从万级原始 prompt 到千级优化后 prompt（如 OpenQA：8530 原始 → 1066 候选 → 1066 优化后；News：120000 原始 → 7600 优化后）。

### 2.2 SFT：教会 optimizer 基本改写能力（§3.2.1）

optimizer 基座论文验证过 BART / RoBERTa-Large / 7B LLM 均可（架构无关），主实验用 **BART**（encoder-decoder，改写任务的自然选择，训练成本远低于 7B LLM）。输入前加任务类型前缀（"This is a ... (generative/question-answering/classification) task."），学习"看到 $P$ → 输出 $P_o$"的基本改写能力。论文引用 Ramamurthy et al. 2022 证明"先 SFT 后 RL"优于直接 RL。

### 2.3 RL：PPO + RRMF 联合训练（§3.2.3，核心创新）

总损失 $L_\rho=\alpha_1 L_{pg}+\alpha_2 L_v+\alpha_3 L_\phi^{r_\theta}$。

**PPO 部分**：标准 policy gradient $L_{pg}=\frac{P_{\pi_a}(t)}{P_{\pi_f}(t)}\cdot(r+\gamma V_{\text{next}}-V_{\text{cur}})$ + value loss $L_v=\|V_{\text{pred}}-(r+V_{\text{next}})\|$，配合 KL 锚定 $L_\phi^{SFT}=-\beta\log\big(\pi_\phi^{RL}(y|x)/\pi^{SFT}(y|x)\big)$ 防止偏离 SFT 模型太远——偏太远会让 reward model 的估计失效。

**RRMF**（**Ranking Responses from Model Feedback**，论文原创命名，类比 RRHF 但对齐"模型反馈"而非"人类反馈"）：

1. SFT 模型对同一原始 prompt 生成 $K$ 个候选改写 $\{y_1,...,y_K\}$
2. **Reward model**（BART 改造：softmax 换成 linear head，输出 scalar）打分 $r_i=r_\theta(x,y_i)$
3. 用**目标 LLM** 计算每个候选的条件 log-likelihood：$p_i=\sum\log P_\pi(y_i|x,y_i)/\|y_i\|$
4. Pairwise rank loss：$L_r=\sum_{r_i<r_j}\max(0,p_i-p_j)$——让 reward 打分更高的候选，在目标 LLM 下的概率也更高
5. Cross-entropy loss（沿用 RRHF）：$L_{ft}=-\sum\log P_\pi(y_i'|x,y_i')$，$y_i'$ 是 reward 最高的 top-1

论文自己的精炼定义（§4.3 消融）："PPO focuses on reducing the dissimilarity between the RL model and the SFT model. **RRMF aligns the scores from the reward model with the likelihood probabilities of an LLM.**" 两者互补：PPO 管策略稳定性，RRMF 管"reward 是否真的对目标模型有意义"。

Reward model 训练数据构造：目标 LLM 对所有候选（含原始 $P$）跑一遍，用同样的 task metric 排序，排名即监督信号——不需要额外标注，靠"排序"代替"打分"，论文原话："discriminative annotation through sorting incurs significantly lower costs compared to generating annotations for answers."

关键超参数（4×A100 80GB，20 epoch）：Learning Rate Actor 2e-5 / Critic 1e-5，PPO Epochs 20，Clip Parameter 0.2，Mini Batch Size 32，GAE Lambda 0.95，最大序列长度 512 tokens。此外借鉴 InstructGPT，从 GLUE+SuperGLUE 取 10% 数据混入训练防止模型过拟合到单一下游任务（generalization maintaining）。

### 2.4 部署机制：证据表明是"per-target-LLM 独立训练"而非"条件生成"

这是容易被误读的地方——MAPO **不是**一个吃"目标模型 ID"当条件输入、就能适配任意模型的统一 optimizer，而是**为每个目标 LLM 单独训练一整套** optimizer + reward model。四条证据：

1. Optimizer 输入只有 `(原始 prompt, 任务类型前缀)`，**没有任何目标模型身份的 token**
2. 实验设置原话："we conduct experiments with three popular LLMs as $\widehat{LLM}$, respectively"——BLOOM/GPT-J/LLaMA 各自独立跑一遍全部流程
3. Case Study 显示 3 个 optimizer 对同一原始 prompt 的改写**风格系统性不同**：BLOOM 偏好主动转被动，GPT-J 偏好"the term used"/"denote"，LLaMA 更口语化——如果是同一个条件化模型，不会出现这种系统性差异
4. warm-up 数据构建本身就依赖"哪个 LLM 在打分"——针对 BLOOM 选出的 $P_o^{\text{BLOOM}}$ 和针对 GPT-J 选出的 $P_o^{\text{GPT-J}}$ 是两份不同数据，reward model 的排序同理是 LLM-specific 的

部署时只需一次前向传播（论文原话："the prompt generation process simply involves a feed forward propagation to generate the optimal prompt instead of further optimization"），但**换一个新目标模型 = 重新走一遍 oracle 生成→选择→SFT→reward model→PPO+RRMF 全流程**。

### 2.5 结果

CloseQA（F1）：Original → SFT → MAPO 依次为 BLOOM 6.4→7.8(+21.9%)→**9.4**(+20.5% over SFT)；GPT-J 6.9→8.4→**10.2**(+21.4%)；LLaMA 10.8→13.9→**14.8**(+6.5%)。PPO-only vs RRMF-only vs 联合（AdverQA F1）：BLOOM 18.8/19.2/**19.5**，GPT-J 9.6/9.9/**11.0**，LLaMA 24.3/24.8/**25.1**——两个组件确实互补而非冗余。Case study 显示平均 normalized edit distance 达 0.67，说明改写幅度很大而非表面润色（仅 ~10% 的 prompt pair 完全不变）。SOTA baseline 对比：除 RLprompt 外，所有已有 baseline（Fine-tuning、Continuous/Discrete prompt tuning）都不超过单纯 SFT，MAPO 在大多数任务上超过 RLprompt。

### 2.6 vs PromptBridge

| 维度 | MAPO（training-based） | PromptBridge（training-free） |
|---|---|---|
| 是否需要 GPU 训练 | 需要（4×A100，SFT+RL 各 20 epoch） | 不需要 |
| 是否需要 oracle | GPT-3.5 生成 1000 候选 + 充当伪 gold | 通常不需要 |
| 换新目标模型的代价 | 必须重跑全流程 | Adapter 一次调用即可 |
| 核心卖点 | 同任务下 prompt per-LLM 自适应 | 从源模型 prompt "翻译"出目标模型 prompt 的能力 |
| 性能上限 | 较高（task+model adaptive 联合优化） | 受限于 prompt-space 搜索能力 |
| 适用场景 | 目标 LLM 固定、资源充足、追求性能上限 | 多 LLM 频繁切换、资源受限、快速迭代 |

## 3. Zero-Shot Continuous Prompt Transfer —— 连续向量的跨架构迁移

**论文**：Wu, Wu & Mou, *Zero-Shot Continuous Prompt Transfer: Generalizing Task Semantics Across Language Models*，Alberta/Huawei/CIFAR，ICLR 2024（[arXiv 2310.01691](https://arxiv.org/abs/2310.01691)，[代码](https://github.com/MANGA-UOFA/PTfer)）

这篇是 4 篇里"迁移"语义最纯粹的——处理对象不是文本，是**连续 prompt（soft prompt）**：$m$ 个虚拟 token 的 embedding 向量 $v_1,...,v_m\in\mathbb{R}^d$，追加在输入末尾，用 OptiPrompt（Zhong et al. 2021）范式训练——冻结主模型，只优化 $v_i$：

$$
\text{Prompt}(x)=x\,v_1v_2\cdots v_m,\qquad \arg\max_{v_1,...,v_m}\sum_{(x,y)\in D}\log P(y|v_1,...,v_m,x)
$$

训练数据是 LAMA-TREx 的 41 个关系子任务，每个关系训一个 soft prompt。

### 3.1 相对空间编码——源侧

直接沿用 Norelli et al. 2022 / Moschella et al. 2023 的 relative representation 思想（"the concept of relative representation involves encoding a data point based on its similarities to certain reference points, known as anchors"）：取源/目标**共享词表**（两者词表的交集）中 $k$ 个 token 的 embedding 作锚点 $A^s=[a_1^s,...,a_k^s]\in\mathbb{R}^{d_s\times k}$，把 soft prompt 向量编码成它与所有锚点的余弦相似度向量：

$$
r_{A^s}(v_i)=\big(\cos(v_i,a_1^s),\dots,\cos(v_i,a_k^s)\big)^\top
$$

实现上先编码到完整相对空间（维度=共享词表大小，约 17,230），再只保留 top-$k$=8192 维、其余置零，规避罕见词噪声（消融验证 8192 是 sweet spot）。相似度函数只用余弦相似度。

### 3.2 核心：目标端怎么"重建"出连续 prompt——梯度搜索 + 重参数化

**这是本文与"检索/查表"式迁移的本质区别**：目标端不是 nearest-neighbor lookup，也不是 closed-form 变换，而是在目标嵌入空间里对一个随机初始化的 $v_i^t$ 做**梯度下降**，让它的相对表征逼近源的相对表征：

$$
r_{A^t}(v_i^t)=\big(\cos(v_i^t,a_1^t),\dots,\cos(v_i^t,a_k^t)\big)^\top,\qquad
\max_{v_i^t}\cos\big(r_{A^s}(v_i),\,r_{A^t}(v_i^t)\big)
$$

$d_t$ 可以 $\ne d_s$——不同维度的模型间也能迁移，这是本文的核心卖点之一。但余弦相似度对向量尺度不敏感，搜出来的 $v_i^t$ 幅度会和目标模型原生词嵌入的统计特性不匹配，必须做**重参数化**：

$$
\tilde{v}_i^t=\frac{v_i^t-\mu_v}{\sigma_v}\cdot\sigma+\mu
$$

其中 $(\mu_v,\sigma_v)$ 是搜出来的所有 prompt 嵌入的均值/标准差，$(\mu,\sigma)$ 是目标模型**原生词嵌入**的均值/标准差——消融显示这一步对跨模型迁移效果至关重要。最后直接用 $\tilde{v}_i^t$ 做目标模型的连续 prompt 推理。整条链：

```
源 vᵢ → 相对表征 r_{A^s}(vᵢ)
      ↓ 梯度下降对齐
目标 vᵢᵗ → 相对表征 r_{A^t}(vᵢᵗ)
      ↓ 统计重参数化
ṽᵢᵗ → 送入目标模型推理
```

多源扩展（§2.4）：把多个源模型的相对表征同时作为优化目标

$$
\max_{v_i^t}\sum_{j=1}^{s}\cos\big(r_{A^{s_j}}(v_i^{s_j}),\,r_{A^t}(v_i^t)\big)
$$

直觉是单源 prompt 携带模型特异性噪声（连续 prompt 高度冗余，Khashabi 2022），多源求和能剥离出更纯粹的任务语义。

### 3.3 跨架构验证——不只是同族模型

主实验在 BERT-base/large、RoBERTa-base/large、ALBERT-base/large 之间做同族/跨族迁移；附录 B.1 进一步测试 encoder→decoder：**RoBERTa-base → GPT-2-large 达 14.33%**（超过 GPT-2-large 手写 prompt 的 10.23%），RoBERTa-base→GPT-2-medium 13.70%（超 8.01%）。注意 ALBERT 因参数共享导致 embedding 与 hidden 绑定，**只能做 target 不能做 source**（可以验证跨家族迁移的接收端）。

Headline 数字：直接迁移几乎完全失效（BERT-base↔RoBERTa-base 仅 0.11–0.12%，BERT-large↔RoBERTa-large 仅 0.49–6.27%），而本文方法：**BERT-base→RoBERTa-base 单源 45.17%**（manual prompt 20.48% 的 2 倍多，是直接迁移的近 400 倍）、**RoBERTa-base→BERT-base 31.33%**、**RoBERTa-large→BERT-base 21.07%**（跨尺寸）、**RoBERTa-large→BERT-large 40.91%**；多源 BERT-base+RoBERTa-base→ALBERT-base 27.13%（单源仅 20.83%，多源增益明显）；分类任务 RoBERTa-base→RoBERTa-large on SST-2 达 84.63%（超过 RoBERTa-large 手写 prompt 的 69.95%）。消融证明 matching loss 与目标 accuracy 单调负相关——相对空间对得越准，迁移效果越好；anchor 数 8192、prompt 长度 5 是 sweet spot。

### 3.4 定位

放进分类法：**Cross-Model Continuous Prompt Transfer**，是目前唯一验证了"跨架构、跨维度"连续 prompt 迁移的工作（横跨同族异尺寸、跨族同尺寸、跨族异尺寸、跨架构四种情形）。局限在于连续 prompt 本身不可读、不可人工审查，且目前只在 encoder-only/decoder-only 的中小模型（BERT/RoBERTa/ALBERT/GPT-2）上验证，尚未看到在当前主流大模型（十亿参数以上、RLHF 对齐）上的迁移证据。

## 4. Transfer-Prompting —— ⚠️ 重要纠正：这篇是跨任务，不是跨模型

**论文**：Chang, Chang & Wu，*Transfer-Prompting: Enhancing Cross-Task Adaptation in Large Language Models via Dual-Stage Prompts Optimization*，吉林大学，2025（[arXiv 2502.14211](https://arxiv.org/abs/2502.14211)，[代码](https://github.com/llm172/Transfer-Prompting)）

**先修正笔记里的定性**：这篇论文虽然在 25 个模型上评测，但**评估时 scorer LLM 始终是同一个 PaLM 2-L**，方法本身不把目标模型身份当输入条件，25 个模型的意义是"证明方法在不同模型上都好用"（model-robust），而不是"为不同模型生成不同 prompt"（cross-model transfer）。论文标题自己写的就是 **Cross-Task Adaptation**，摘要与 §1 贡献 #1 都在强调"cross-task adaptability"，§3.1 明确说"source task dataset is constructed by selecting related tasks from multiple datasets within the same domain"——强调的是 task/domain，不是 model。它属于类别一"离散文本自动优化"的一个变体，放进类别二的唯一理由是"跨任务迁移"和"跨模型迁移"在直觉上容易混淆，值得单独拎出来对比。

### 4.1 双阶段算法——机制完全相同，只是数据集和起点不同

核心工具：Reference LLM（生成候选，论文用 PaLM 2-L/PaLM 2-L-IT/GPT-3.5-Turbo/GPT-4）+ Scorer LLM（统一用 PaLM 2-L 评分）+ 每轮 8 个候选的生成-评估-筛选循环（"at each training step, the reference LLM generates 8 refined prompts"）。

**Stage 1（Source Prompt Construction，§3.3）**：从原始 prompt 出发，在 $\kappa$ 个**同领域相关任务**数据集上优化，得到泛化的高分指令集：

$$
P_{\text{source}}=\arg\max_{P}\sum_{P\in\mathcal{P}}\sum_{i=1}^{\kappa}\sum_{m\in M}w_m\cdot\phi_m(P,D_{S_i})
$$

**Stage 2（Target Prompt Generation，§3.4）**：从 $P_{\text{source}}$ 里挑出最高分的作为**起点**，在单一目标任务数据集上做专门化优化：

$$
P_{\text{target}}=\arg\max_{P}\sum_{P\in\mathcal{P}}\sum_{k=1}^{\tau}\sum_{m\in M}w_m\cdot\phi_m(P,D_{T_k})
$$

两阶段唯二的区别：起点（Stage 2 从 $P_{\text{source}}$ 出发而非原始 prompt）和数据集（Stage 1 是多相关任务并集，Stage 2 是单一目标任务，$\tau$ 通常=1）。本质是"先学领域通用指令，再在目标任务上微调措辞"的渐进式专门化，每轮迭代直到 reference LLM 无法生成更高分 prompt 或达到步数上限。

### 4.2 5 维评分——与 OPRO 的差异化卖点

OPRO 只用单一指标，本文用 5 个从 scorer LLM logits 计算的指标等权重取算术平均：ACC（准确率）、1−ECE（校准误差反转）、ROC-AUC、PR-P（正类 PR-AUC）、1−PR-N（负类反转）。

### 4.3 25×9 实验矩阵的真实构成

7 个通用模型（GPT-3.5-Turbo/GPT-4/LLaMA-2-7B/13B/LLaMA-3-8B/Vicuna-7B/13B，测 LogiQA/OpenbookQA/CosmosQA）+ 18 个领域专用模型（医学 6 个：ChatDoctor-13B 等；法律 6 个：DISC-LawLLM-13B 等；金融 6 个：CFGPT-7B-Full 等，各自测对应领域数据集如 MMLU/CMMLU/MedMCQA/AGIEval/FinEval）。**注意不是 25×9 全交叉矩阵**，每个模型只在自己的数据集子集上评估。

Headline：GPT-4 on LogiQA，IFR（指令遵循率）0.70→0.82（+0.12），ECE 0.30→0.18（−0.12）；Medicine-LLM-13B on MMLU Medical，ACC 0.52→0.64（+12pp），ECE 0.34→0.15（−56%）；在 MMLU Medical 上持续超过 OPRO/Iterative-APE/PromptAgent/APO 四个 SOTA baseline，且 train/test gap 小、不显著过拟合。

### 4.4 对分类法的影响

正确的位置是 **Cross-Task / Cross-Domain Discrete Prompt Optimization**，机制上是 OPRO 风格迭代优化的两阶段特化版。与本篇其他三篇论文的本质区别：PromptBridge/MAPO/Zero-Shot Continuous 三篇都在解决"同一任务、换模型"，Transfer-Prompting 解决的是"同一模型、换任务"——方向正好相反。

## 5. DSPy 的"编译"到底是什么（补充，呼应 [[3. Adaptive prompt for diff LLM]] 类别二表格）

DSPy 不是一个独立优化算法，是一个把 prompt 当**可编译程序参数**的框架：声明式模块（Signature + Module）描述"要做什么"，编译器（如 MIPRO，详见 [[2. Agent Prompt Auto Opt]]）针对**给定的目标 LM + 指标**，自动搜出 instruction + few-shot demo 的组合。同一段 DSPy 程序换一个目标 LM 重新编译一次，就能得到为该 LM 定制的 prompt——这是第 5 种"跨模型适配"范式：**不迁移、不训练 optimizer，而是每次换模型都重新编译/搜索一遍**，成本和 MAPO 类似（每模型独立跑），但搜索空间是离散的 instruction/demo 组合而非训练一个 seq2seq 改写器。

## 6. 五种范式速查表

| 范式 | 代表 | 换新模型的代价 | 输出可读性 | 迁移 vs 独立优化 |
|---|---|---|---|---|
| Training-free 文本翻译 | PromptBridge | 极低（1 次 LLM 调用） | 高（自然语言） | 迁移 |
| Per-model 训练改写器 | MAPO | 高（重训 SFT+RL） | 高 | 独立优化（伪装成"适配"） |
| 连续向量重建 | Zero-Shot Continuous Transfer | 中（梯度搜索，无需重训模型） | 低（不可读向量） | 迁移 |
| 跨任务优化 | Transfer-Prompting | N/A（不是跨模型问题） | 高 | 既非迁移也非模型适配 |
| 重新编译 | DSPy/MIPRO | 中（重跑搜索/优化） | 高 | 独立优化 |

**回到最初的问题**（同一个 agent 功能，不同 LLM 用不同 prompt 保持等价行为）：PromptBridge 是目前唯一直接给出"低成本、可解释、training-free"答案的工作；DSPy/MIPRO 是"每个模型都重新搜一遍"的稳健但较重的备选；MAPO 提供了"如果愿意付训练成本，性能上限更高"的路径；Zero-Shot Continuous Transfer 证明了"即使连续向量、跨架构"也存在可学习的迁移结构，是理论上最有延展性但工程上最不成熟的方向。

## 7. 局限与适用边界：这套方法论到底在优化什么、买的是什么

### 7.1 优化对象的真实尺度：任务级中等长度模板，不是短对话轮次，也不是长文件 system prompt

四篇论文优化的都不是"每轮用户短输入"，也不是"含多个大文件的长 system prompt"，而是卡在中间——一个跨大量实例复用的、中等长度的任务指令模板：MAPO/Transfer-Prompting/Zero-Shot Continuous Transfer 是一句话到一段话的 NLP 指令（Zero-Shot Continuous Transfer 甚至只是 5 个虚拟 token 的向量）；PromptBridge 的 Adapter prompt 实测几百词；AutoPDL 的 PDL 模板+0/3/5 个示例。核心区分：优化的永远是"模板 $p$"，$x$（具体问题/代码/用户输入）是变量，不参与优化，只是套进模板——不管 $x$ 多长多短，被优化的东西本身都不大。

**没有一篇论文测过"prompt = 包含多个大文件的生产级 agent system prompt"这个场景**，这不是同一个问题的小号版本，而是尺度/机制都不同的另一个问题：真实生产 agent system prompt（OpenCode/Claude Code/Codex CLI/Cursor 等）实测 2,300–22,500 token，比这里的"任务包装层"大 5–50 倍，核心矛盾也从"措辞对不对"变成"该放哪些内容、怎么排序"（检索/压缩/结构化）——这些论文的 fitness/behavior 打分机制不是为此设计的，迭代改写的成本模型在这个尺度下也不成立。这个更大的问题已经单独开了一篇：[[9. 长 Agent System Prompt 跨模型可移植性]]。

### 7.2 "性能上界"不可知，只有代理指标

$p^*_{M,T}=\arg\max_p A(M,T,p)$ 里的 argmax 从未真正求解——prompt 空间不可枚举，没有任何方法能给出真上界，只有三种代理：

1. **收敛/平台信号**：ProTeGi 论文自述"约第 3 步达到峰值，之后过拟合或陷入局部最优"（见 [[2. Agent Prompt Auto Opt]]）——只说明当前搜索策略在当前预算下已到头，不是全局最优
2. **"作弊"基线当乐观参考**：PromptBridge Table 4 里 MIPROv2\*/GEPA\* 被显式标注"直接在 test benchmark 上优化（过拟合上限参考）"——连作者自己都只能用允许偷看测试集的版本当参照物
3. **模型能力天花板 ≠ prompt 措辞天花板**：prompt 优化的真正上界由模型的潜在推理能力决定，跟怎么写 prompt 无关；prompt engineering 只能把实际表现逼近这个能力天花板，永远不能让模型超出自身容量，而这个天花板本身也只能靠"换更多方法、更大预算后数字还是卡在同一处"来间接估计

### 7.3 跨模型迁移 vs 直接在目标模型上单模型优化：不是同一件事，但也不是"魔法"

**共同点（唯一的 ground truth）**：两者最终都要靠"把 prompt 丢到目标模型 B 上跑一遍"验证好坏，迁移方法不掌握任何 B 不知道的信息——从这个角度看，跨模型迁移确实不是一个本质不同的问题，而是单模型优化问题的一种"带先验/热启动"变体。

但迁移不等于"什么都不做"，也不总是弱于直接优化——PromptBridge 自己的 Table 1（源=GPT-4o，Pass@1）把"直接在 B 上单模型优化"（MIPROv2、GEPA，均不加星号，非作弊）和跨模型迁移结果放在一起比：

| Target | Direct Transfer | MIPROv2（直接在 B 上优化） | GEPA（直接在 B 上优化） | PromptBridge（跨模型迁移） |
|---|---:|---:|---:|---:|
| o3 / HumanEval | 92.27 | 93.70 | 96.95 | **97.15** |
| o4-mini / CodeContests | 40.12 | 48.28 | 55.15 | **58.79** |
| Llama-3.1-70B / HumanEval | 68.70 | 78.25 | **35.98**（比什么都不做还差） | **79.88** |

GEPA 在 Llama-3.1-70B 上直接优化甚至崩到比 Direct Transfer 还差——"直接在目标模型上优化"不是稳定免费的替代品，单模型搜索本身会卡在局部最优甚至搜偏方向；迁移用的是"跨任务比较稳定的编辑模式"当先验，反而绕开了这些坑。

**正确框架**：跨模型迁移本质是"带先验/热启动的单模型优化"，赌的是"哪种 prompt 编辑对这个任务有用"这件事在不同模型间比在不同任务间更稳定。PromptBridge 附录里的 transfer-gap cosine similarity 分析，本质就是在实证检验这个赌注——赌对了（模型间结构共性 > 模型特异性）比从零搜索更高效甚至更好；赌错了（换到论文没测过、对齐方式差异很大的模型，如 Mistral/DeepSeek）大概率退化成不如直接优化，这也是该方法真正的适用边界所在。

### 7.4 "先在便宜模型上优化再迁移省钱"：思路对了一半

PromptBridge 的经济模型不是"完全绕开贵模型"——calibration 阶段**必须在目标模型（贵的那个）上也完整跑一遍 MAP-RPE**，只是这笔成本在校准阶段付一次，之后新任务通过 Adapter 一次 LLM 调用免费复用。省的是"每个新任务都要重新在贵模型上搜索"，不是"完全不用贵模型"。

**推论**：如果只有一个任务、一个目标模型（没有多任务摊销的场景），整套跨模型迁移机制反而是纯粹的额外开销——正确做法是跳过类别二，直接用类别一的单模型方法（TextGrad/ProTeGi/PMPO，见 [[2. Agent Prompt Auto Opt]]）在目标模型上优化。

真正可行、且已有先例的省钱思路是**解耦"提议候选"与"打分评估"**——TextGrad 就是这么做的（强模型当梯度引擎优化弱模型的 prompt，见 [[2. Agent Prompt Auto Opt]] 1.2 节），方向可以反过来：便宜模型生成候选编辑，只在贵模型上做最终打分。这能省"改写"这一步的调用成本，但**打分这一步省不掉**——"这个 prompt 在贵模型上好不好"只能从贵模型自己身上问出来，没有代理能替代。真正能减少评估次数的杠杆是 AutoPDL 式的 successive halving（见 [[3.2. Agent 场景 Prompt 优化深度解读]]）：先用小验证集快速淘汰明显差的候选，把预算集中花在少数幸存者上，而不是妄图完全跳过对贵模型的评估。
