# Self-Evolution 方法论对照：Harness 层 vs 权重层

> 范围：[[4.2. RSI 产业进展与 MetaEquipe 案例分析]] 的深入进阶版——4.2 用产业操作性定义判断"MetaEquipe 是不是 RSI"，本文换一个角度：把 **Harness 层**（DGM / ADAS / AlphaEvolve / Promptbreeder，改代码/prompt，模型权重冻结）和**权重层**（SEAL / SPIN / Self-Rewarding LMs / STaR，直接改 θ）按同一套七维度逐一对照，回答"harness 自进化和权重自进化到底差在哪"，并附上一个额外维度——**收益曲线的实际形状**（这是本文单独补的调研，之前的深度解读没查过）。
> 结论先行：两者在**起点门槛**、**reward 计算成本结构**、**多样性维护能力**、**收益曲线形状**四个维度上系统性不同，且这四条不是互相独立的巧合——都源自同一个底层差异："改的对象能不能并存多个版本"。代码/config 天然容易分叉、并存、回退；权重每次更新基本是覆盖式的，这决定了后面所有差异。

---

## 0. 七个对照维度（复用自 [[MetaEquipe 打造任意AI agent 团队]] 2.2.2–2.2.9 的框架）

1. **改进对象/表示**——改的是代码、prompt 还是权重 θ？
2. **起点/种子**——需要什么样的初始状态才能开始？
3. **Optimize 机制**——具体怎么从当前版本产出更好的候选？
4. **Benchmark/reward 设计**——怎么判断候选是不是真的更好？
5. **多样性/archive 维护**——是单链演化还是维护多个并存版本？
6. **成本量级**——真实跑一次要花多少钱/算力？
7. **收益曲线**——论文有没有画出"分数 vs 迭代轮数"的图，形状是什么？

## 1. Harness 层自进化（改代码/prompt，模型权重冻结）

### 1.1 概览表

| 维度 | DGM | ADAS | AlphaEvolve | Promptbreeder |
| --- | --- | --- | --- | --- |
| 改进对象 | 代码（agent 自身 Python：`coding_agent.py`、工具、prompt） | 代码（`forward()` 函数，图灵完备） | 代码/算法（任意程序：矩阵乘法、调度、芯片脚本） | 纯文本 prompt（task-prompt + mutation-prompt） |
| 起点 | 初始 coding agent 实现 | 人工设计的初始 agent 集合 | 可以很朴素的初始程序 | 人工种子 prompt |
| Optimize 机制 | o1 诊断问题 + Claude 3.5 Sonnet 实现修改，产出 diff | Meta agent（gpt-4o）依据完整 archive 历史提案候选，2 轮自我反思 + debug_max=3 重试 | LLM 生成 SEARCH/REPLACE diff，MAP-Elites 网格×island 管理，采样 1 parent + 2-4 inspiration | 9 种变异算子（含 hypermutation），binary tournament 选择 |
| Benchmark | SWE-bench Verified / Polyglot 通过率 | ARC/DROP/MGSM/MMLU/GPQA，n_repeat=5(GPQA)+bootstrap CI，held-out test 集事后评估 | 自定义评测器 cascade（由粗到细过滤） | 100 题训练 batch 准确率 |
| 多样性/archive | 扁平列表，默认 `keep_all`，父代选择=sigmoid质量×逆子代数novelty | 扁平列表，全部存盘 | MAP-Elites 网格（行为特征分格）×island（周期迁移），格内 keep-better 替换 | population=50，单代无跨代 archive |
| 成本 | ~$22,000/80 迭代（SWE-bench），~$275/iter，60-task 中间评测 $350/次 | ARC ~$500/25 迭代（~$20/iter），推理域 ~$300/30 迭代（~$10/iter） | 不披露 $，100 CPU-hrs/次评测（可并行），千级 LLM 样本（比 FunSearch 少 ~1000×） | 不披露 |

引用：DGM [arXiv:2505.22954](https://arxiv.org/abs/2505.22954)；ADAS [arXiv:2408.08435](https://arxiv.org/abs/2408.08435)；AlphaEvolve [arXiv:2506.13131](https://arxiv.org/abs/2506.13131)；Promptbreeder [arXiv:2309.16797](https://arxiv.org/abs/2309.16797)。

### 1.2 安全/部署（四者共同的空白）

DGM §5：安全论述止步于"沙箱隔离+严格超时+范围限定在改代码库本身+人工看 archive 记录"，接受标准就是 `if c.is_valid()`。ADAS §6：同样止步于"容器化执行+人工检查+代码警示"。AlphaEvolve、Promptbreeder 论文完全未讨论部署安全。**四者都没有灰度/影子运行/生产验证机制**——这一点已经在 [[MetaEquipe 打造任意AI agent 团队]] 2.2.8 里核实并记录。

### 1.3 收益曲线：harness 层普遍"撑到预算耗尽都还在涨"

- **DGM**（[Fig 3 右图](https://arxiv.org/html/2505.22954v3)）：best-in-archive-so-far 曲线在全部 80 轮内单调上升，SWE-bench 20.0%→50.0%，Polyglot 14.2%→30.7%，**80 轮内未出现平台**；最优 lineage 有两次明显下探（"垫脚石"现象——先变差、后续才带来更大突破）；ablation（Fig 5/6）显示只有完整版（open-ended + self-improve 都开）能持续上涨，阉割版本都早早平台。
- **ADAS**（[Fig 3(a)](https://arxiv.org/html/2408.08435v2)）：ARC 测试准确率+95% CI vs 迭代 1-25，**阶梯式**，论文明确标注突破点：迭代 3（多 CoT+ensemble）、5（多样反馈）、11（效率/简洁专家）、12（类人反馈）——到第 12/25 轮仍在产出新突破，未平台。
- **AlphaEvolve**（Fig 8）：**没有**逐代分数曲线，只有"计算预算 vs 效果"的消融对比（4 种配置：无 meta-prompt/无全文件/仅小模型/完整版），"比 FunSearch 少 1000× 样本"只是 Table 1 里的一个数字对比，不是曲线。
- **Promptbreeder**（Fig 3）：**只有 APE Word-in-Context 一个任务**画了 fitness vs ~2000 次评测的曲线（持续上升，2000 次评测内未平台），GSM8K/SVAMP 等主 benchmark 只有最终数字，没有逐代曲线。

## 2. 权重层自进化（直接改模型参数 θ）

### 2.1 概览表

| 维度 | SEAL | SPIN | Self-Rewarding LMs | STaR |
| --- | --- | --- | --- | --- |
| 改进对象 | 权重（LoRA SFT）；self-edit 是自然语言（知识注入=implications 列表，few-shot=JSON 配置） | 权重（DPO 风格 loss，θ_t 同时是被更新者和 frozen 对手） | 权重（迭代 DPO，作者测过纯 SFT 不 work） | 权重（标准 SFT，next-token 交叉熵） |
| 起点 | Qwen2.5-7B/3B base、Llama-3.2-1B-Instruct，**无需**领域 SFT | **必须**已 SFT 过的模型（zephyr-7b-sft-full） | 预训练 Llama2-70B（无 FT）+ 3200 条 IFT + 1630 条 EFT | GPT-J-6B，每轮**从原始预训练权重重新初始化**，10 个种子理由 |
| Optimize 机制 | ReST^EM（filtered behavior cloning）；GRPO/PPO 试过因不稳定被弃用 | 单人自我博弈：同一模型扮演 discrimination game 两方 | 模型自己当 judge，固定 5 点量表打分 | Rationalization：答错时把正确答案当 hint 塞进 prompt，倒推出理由，训练时再把 hint 去掉 |
| Benchmark | 知识注入=无 context SQuAD EM；few-shot=ARC 0/1 是否答对 | SFT 数据本身是隐式 reward，无显式 RM | 模型自己的判断是唯一 reward，RM(=generator)每轮跟着自己更新 | 纯规则过滤（答案是否正确），无学习型 reward |
| 多样性/archive | 单链，θ′ 每轮从当前 θ 重算，从不提交，无 archive | 单链 θ₀→θ₁→θ₂→… | 严格线性 M1→M2→M3，无 archive | 单链，重复到"饱和"为止 |
| 成本 | 单次 reward=30-45 秒（含真实 LoRA 微调+下游评测），知识注入 750 次 inner 迭代≈6h/2×H100 | 50k UltraChat200k prompts，8×A100，每 iter≈10h，4 轮≈120 A100-hrs | 仅 2 轮 AIFT，数据集≤7k 对 | GPT-J 规模，算术 16-20 轮，GSM8K 上限 30 代/7912 步 SFT |

引用：SEAL [arXiv:2506.10943](https://arxiv.org/abs/2506.10943)；SPIN [arXiv:2401.01335](https://arxiv.org/abs/2401.01335)；Self-Rewarding LMs [arXiv:2401.10020](https://arxiv.org/abs/2401.10020)；STaR [arXiv:2203.14465](https://arxiv.org/abs/2203.14465)。

### 2.2 安全/部署：两个明确点名的结构性风险

- **SEAL** §5：无验证门（只有 reward filter），**灾难性遗忘被承认并测量**（Fig 6：早期任务性能随编辑积累下降）；第三个限制——每个 context 必须配显式下游 label/QA，不能对开放式输入自我编辑。
- **SPIN**：零安全分析，只有理论上的 KL 防塌缩论证（eq 4.1 里的参照项）。
- **Self-Rewarding LMs**：**reward hacking 被作者明确点名为未解决风险**——judge 和 generator 共享权重，理论上模型可以学会利用自己的评分标准；NLP 基准性能下降（ARC-C 55.97→53.13 等"对齐税"）；输出长度膨胀（1092→2552 token）被怀疑是虚假增益。
- **STaR**：明确警告"理由不保证忠实"（不代表模型真实推理过程），正确率过滤器可能放大数据集偏见。

### 2.3 收益曲线：权重层普遍"2-3 轮就饱和或分阶段卡住"

- **SEAL**（Fig 4）：无 context SQuAD 准确率 vs ReST^EM 迭代，iter 0→1 陡升，**iter 2 超过 GPT-4.1 合成数据基线后饱和**。论文原话："两轮足以让 SEAL 超越 GPT-4.1 数据；后续迭代收益递减，说明策略快速收敛"（§4.2）。
- **SPIN**（Fig 3）：2-3 轮后明显收益递减，iter 0→1 是最大跳跃；作者称这正是为了避免"continued SFT 会到达平台甚至分数下降"的问题，但没做遗忘/安全消融。
- **Self-Rewarding LMs**：只有 M1→M2→M3 两次跳跃的 win rate 数字（15.38%→20.44%），样本点太少不构成真正的"曲线"；NLP 基准反而是一条下降曲线。
- **STaR**（Fig 4/5）：n 位数加法准确率 vs 迭代 1-16，**不带 rationalization 是阶梯式**——必须先学会 (n-1) 位才能学 n 位；**带 rationalization 后"同时学习多个长度"**，2 位数准确率能在带 rationalization 情况下一轮内从 <1%→32%；16 轮后整体 89.5% vs 不带 rationalization 的 76.3%。

## 3. 两层对照：四个系统性差异

1. **起点门槛不同**：harness 层几乎没有门槛（DGM/ADAS/AlphaEvolve 都能从很朴素的初始代码开始）；权重层普遍**要求已经 SFT 过的模型**（SPIN 明确写"必须从弱模型出发，但弱是相对于数据的弱，不是完全没训练过"），SEAL 是例外（可以从 base 模型直接开始）。

2. **reward 计算成本结构不同**：harness 层"评一次"通常就是跑一次 benchmark；**SEAL 的 reward 必须先做一次真实的 LoRA 微调才能算出来**（30-45 秒/样本，还是最便宜的知识注入场景），这笔成本不可压缩，没法像 ADAS 那样用"便宜模型先筛一遍"降本。

3. **多样性维护能力不同**：DGM 用扁平 archive（keep_all）、AlphaEvolve 用 MAP-Elites 网格，都能维护多个并存版本；**权重层四个系统全部是单链**（θ₀→θ₁→θ₂ 或 M1→M2→M3），没有一个维护多个权重快照的并行探索——大概是因为权重快照的存储/管理成本远高于保留一份代码或一份 prompt。

4. **收益曲线形状不同（本文新查）**：**harness 层能撑到预算耗尽都还在涨**——DGM 的 best-in-archive 曲线 80 轮内不平台，ADAS 到第 12/25 轮仍在产出突破；**权重层普遍 2-3 轮就饱和或分阶段卡住**——SEAL 明确在 iter 2 饱和，SPIN 2-3 轮递减，Self-Rewarding 只跑 2 轮就怀疑饱和，STaR 不带 rationalization 时甚至会卡在某个阶段上不去。

   **但这条结论的证据边界要说清楚**：AlphaEvolve 和 Promptbreeder 都没有发布同等的逐代性能曲线（AlphaEvolve 只有计算预算消融，Promptbreeder 只有单个任务的示例曲线），所以严格来说第 4 条差异主要靠 DGM/ADAS vs SEAL/SPIN/STaR 四篇成立，不能说"所有 harness 层工作都完胜所有权重层工作"——只能说**已发布轨迹曲线的样本里，harness 层这几篇确实撑得更久**。第 1-3 条差异证据更充分，是四个系统 vs 四个系统全部符合。

这四条也回应了 [[MetaEquipe 打造任意AI agent 团队]] 里"为什么选 harness 层不选权重层"的隐含设计判断：门槛低、reward 便宜、天然支持多样性维护、经验上收益曲线撑得更久——四个理由都指向同一个方向。

## 4. 结构性风险：优化器和评判者同源，MetaEquipe 也要小心

Self-Rewarding LMs（judge 和 generator 共享权重，reward hacking 未解决）和 STaR（理由不保证忠实）分别在权重层点名的风险，和 MetaEquipe 的 **Meta Optimizer** 结构是同构的：Meta Optimizer 用 `H_guide` 自己的策略去指导对 Task1/2/3 的优化，又用相近的 benchmark 机制给 `H_guide` 打分——本质上也是"决定怎么改"和"评判改得好不好"共享着同一套底层逻辑（都来自同一个 LLM 家族/同一套 prompt 设计哲学）。这条风险目前 [[MetaEquipe 打造任意AI agent 团队]] 2.2.7/2.2.8 都还没有专门讨论，建议下一步补充。
