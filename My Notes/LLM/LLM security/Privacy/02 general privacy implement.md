# Privacy 通用层实施路线

> 目标：为 LLM Agent 建立一个与文件格式、业务领域解耦的基础隐私引擎，优先保护个人信息、凭证、秘密和组织机密。
>
> 当前基础：通过轻量语言模型识别本地文件中的敏感内容，替换为占位符后发送给大模型，再将输出中的占位符恢复。当前支持 DOC、CSV、Excel。

## 0. 实施结论

第一阶段不要为 DOC、CSV、Excel、医疗、法律、财务分别训练独立模型。推荐拆成三类组件：

```text
Extractor：负责从不同文件/消息格式中完整提取内容
Detector：负责识别敏感实体、秘密和上下文
Policy：负责决定放行、删除、替换、阻断或人工确认
```

总体流程：

```text
文件 / 消息 / 工具结果
        ↓
格式专用 Extractor
        ↓
统一文本/表格中间表示
        ↓
分层 Entity Detector
        ↓
Policy Decision
(allow / redact / tokenize / block / review)
        ↓
本地映射与发送
        ↓
模型输出复检
        ↓
恢复 / 阻断 / 外发审批
```

核心原则：

1. 能不发送原文，就不要发送原文；
2. 小模型是候选发现器，不是唯一安全裁决器；
3. 高风险秘密默认阻断，不做自动恢复；
4. 可逆 Token 的映射表是高价值秘密，必须本地隔离和加密；
5. 输入、输出、Memory、Cache、Log 和 Trace 都要纳入数据流治理。

## 1. 通用层的范围

### 1.1 直接个人信息

- 姓名
- 邮箱
- 手机号
- 地址
- 身份证、护照、驾照等证件号
- IP、设备 ID、Cookie、位置
- 账号和用户标识

### 1.2 认证材料和秘密

- 密码
- API Key
- OAuth Token
- JWT
- SSH Key
- 云凭证
- 数据库连接串
- 内部服务 Token

### 1.3 财务和支付信息

- 银行卡号
- 银行账户
- 支付账号
- 发票号
- 交易编号

### 1.4 组织机密

- 内部项目名
- 客户编号
- 合同编号
- 内部 URL
- 数据库表名
- 未公开代码和配置
- 商业计划和内部业务数据

第一阶段不追求覆盖所有法律、医疗和行业语义。先保证跨领域、可验证、高价值实体稳定工作。

## 2. 统一数据模型

### 2.1 Canonical Representation

不同格式先转换为统一中间表示，至少保留：

- 文本内容；
- 表格、单元格和字段结构；
- 段落、页码、行列、字符区间等位置；
- 来源文件、来源字段和数据类型；
- 元数据、批注、隐藏内容和嵌入对象；
- 原始内容的本地 hash；
- 解析器版本和解析置信度。

隐私检测使用统一中间表示；格式差异由 Extractor 和回写器负责。

### 2.2 Entity Schema

每个检测结果至少包含：

```json
{
  "entity_type": "EMAIL",
  "start": 120,
  "end": 145,
  "confidence": 0.99,
  "detector": "regex_email",
  "sensitivity": "personal",
  "action": "tokenize",
  "scope": "task-123",
  "source": "document.body",
  "policy_version": "privacy-v1",
  "transform": "task_token",
  "restore_allowed": true
}
```

建议字段：

- `entity_type`：实体类型；
- `location` / `start` / `end`：原文位置；
- `confidence`：检测置信度；
- `detector`：使用的检测器；
- `sensitivity`：敏感级别；
- `source`：文件、字段、工具结果或 Memory 来源；
- `policy_version`：决策策略版本；
- `transform`：删除、遮蔽、Tokenization 等；
- `task_scope`：任务、用户、租户和会话边界；
- `restore_allowed`：是否允许恢复原文。

## 3. 分层检测器

### L0：来源、权限和元数据

在读取正文前先判断：

- 文件所有者和来源；
- 是否允许外发；
- 数据分类和租户；
- 文件是否包含宏、嵌入对象、隐藏内容或未知格式；
- 当前 Agent 和任务是否有读取权限。

### L1：Regex + 校验器 + Secret Scanner

优先实现高精度、可解释的结构化检测：

- 邮箱；
- 手机号；
- 身份证、护照和驾照号；
- 银行卡号和账户号；
- IP 地址；
- API Key、Token 和连接串；
- JWT；
- SSH Key；
- 密码字段和高熵秘密。

仅用 Regex 容易误报，因此需要长度、校验位、前后文、国家/地区格式和 Secret Scanner 规则共同判断。

### L2：通用 NER / 轻量分类器

处理规则难以覆盖的自然语言实体：

- 人名；
- 地名和地址；
- 组织名；
- 日期和时间；
- 用户名、客户名和账号描述；
- 自然语言中的个人关系和身份描述。

NER 只能识别“可能是实体”，还需要 Policy 判断是否敏感、是否需要脱敏。

### L3：上下文模型

只对候选片段或高风险上下文调用小型语言模型：

- “苹果”是水果、公司还是客户姓名；
- “王医生”是公开人物还是病历中的患者；
- “项目 Falcon”是普通词还是内部项目名；
- 一组普通字段合在一起是否足以识别个人。

模型应输出：实体类型、敏感级别、证据片段、置信度和建议动作，而不是直接获得恢复映射表或直接放行权限。

### L4：人工复核和组织策略

以下情况进入人工或组织级策略：

- 法律、医疗、财务等高敏感数据；
- 低置信度但高影响的候选；
- 需要恢复原文并外发；
- 规则冲突、模型不确定或跨租户数据；
- 客户自定义字段和例外授权。

## 4. 处理动作

第一版不要只有“替换”一种动作：

| 动作 | 说明 | 适用情况 |
|---|---|---|
| `allow` | 原样保留 | 低风险、公开或明确获授权的数据 |
| `redact` | 删除或遮蔽，不能恢复 | 模型不需要原文；高风险秘密 |
| `tokenize` | 替换为任务级 Token，可在本地恢复 | 需要保持实体一致性且任务确实需要恢复 |
| `block` | 不继续处理或不发送 | 密码、SSH Key、高风险凭证、无法安全判断的数据 |
| `review` | 暂停并请求用户或管理员确认 | 高影响、低置信度、外发或法律/医疗/财务场景 |

示例：

```text
邮箱       → <EMAIL_a81f>
身份证号   → <ID_92ab>
API Key    → block
普通姓名   → 根据任务策略 allow / tokenize
病历事实   → 默认 redact 或 review
```

## 5. Tokenization 实施要求

当前方案属于**可逆伪名化/Tokenization**，不应称为匿名化。

### 5.1 Token 设计

不要使用：

```text
张三 → <PERSON_001>
```

也不要使用包含敏感语义的 Token：

```text
<CANCER_PATIENT>
<VIP_CUSTOMER>
```

推荐使用任务级、随机、低语义的 Token：

```text
张三 → <PERSON_a81f>
```

### 5.2 映射表保护

- 每个任务独立映射表；
- 映射表只留在本地；
- 映射表加密；
- 不进入 Prompt、普通日志、Memory 或工具参数；
- 不同租户和不同任务不复用 Token；
- 任务结束后过期、销毁或按授权保留；
- 恢复操作需要单独权限和审计。

### 5.3 输出恢复前复检

恢复 Token 前检查：

- 输出目的和接收者；
- 用户、任务和字段权限；
- 是否发生新的外发或副作用；
- 模型是否生成了新的 PII 或秘密；
- 是否出现 Token 残留、原文残留或结构破坏。

如果输出要发送邮件、写入外部系统、发布或部署，不能因为输入已经脱敏就自动恢复。

## 6. 文件格式支持路线

需要逐个文件类型做**解析器、回写器和覆盖测试**，但不需要逐个文件类型维护独立隐私识别模型。

| 阶段 | 格式 | 关键检查 |
|---|---|---|
| P0 | Text / Markdown / JSON / CSV / DOCX / XLSX | 正文、表格、字段、单元格、公式、批注、隐藏 sheet、文档元数据 |
| P1 | PDF / 图片 / Screenshot | 文本层、扫描页、OCR、图片中的证件、人脸、二维码、页码和布局 |
| P1 | Email / HTML | 正文、HTML 属性、链接、签名、引用历史、附件和隐藏内容 |
| P1 | Code / Log | API Key、Token、连接串、路径、用户名、堆栈和业务数据 |
| P2 | Archive | 内层文件、目录名、嵌套压缩、宏/对象、大小/深度限制和压缩炸弹 |

### 当前 DOC、CSV、Excel 的补强重点

- DOCX：批注、修订、页眉页脚、文档属性、嵌入图片和对象；
- CSV：编码、分隔符、公式注入、字段类型和超长行；
- XLSX：隐藏 sheet、隐藏行列、公式、批注、命名区域、数据验证和嵌入对象；
- 所有格式：解析失败或无法确认覆盖范围时，默认不发送原文。

## 7. 通用层最小实现顺序

### Phase 0：定义边界和数据分类

建立最小数据分类：

```text
Public
Internal
Personal
Sensitive Personal
Secret / Credential
High-risk Domain Data
```

同时定义：

- 哪些数据允许发送给哪些模型；
- 哪些数据必须本地处理；
- 哪些数据必须阻断；
- 哪些动作需要用户或管理员确认；
- 原文、映射表、输入、输出、Memory、Cache、Log 的留存时间。

### Phase 1：统一实体和策略框架

交付物：

1. Entity Schema；
2. 统一 Canonical Representation；
3. `allow / redact / tokenize / block / review` 策略接口；
4. 任务、用户、租户和会话 scope；
5. 本地加密映射表服务；
6. 策略版本和审计事件格式。

### Phase 2：实现基础检测器

顺序建议：

1. Email、手机号、身份证件、银行卡等结构化 PII；
2. API Key、Token、SSH Key、密码和连接串；
3. Regex + 校验器 + Secret Scanner；
4. 通用 NER；
5. 候选上下文模型；
6. 人工复核和例外策略。

### Phase 3：接入当前 DOC、CSV、Excel

先不扩展格式，建立基准集并测量：

- 检测 precision / recall / F1；
- 原文残留率；
- 敏感组合漏检率；
- Token 一致性和恢复率；
- 表格结构和公式保持率；
- 解析失败率；
- 输出中的新生成 PII；
- Memory、Cache、Log、Trace 中的明文暴露率。

### Phase 4：扩展解析器

按用户价值和隐私风险增加 PDF/OCR、Email/HTML、Code/Log、Archive。新增格式时只新增 Extractor、回写器和格式测试，不复制 Detector 与 Policy。

### Phase 5：增加领域策略包

只有在以下情况出现时才增加医疗、法律、财务或 HR 策略包：

- 通用层漏检/误检代价明显高；
- 实体定义严重依赖领域上下文；
- 数据分类和处理规则明显不同；
- 客户有明确的字段、词汇和审批需求。

领域包组成：实体类型、词表、正则、校验器、NER/分类器适配、敏感等级、变换策略、阻断规则、人工复核和回归集。

## 8. Agent 全链路 Privacy

### 8.1 发送前

- 数据最小化：只发送完成任务所需字段和片段；
- 检查文件和任务权限；
- 根据数据等级选择本地模型、企业模型或外部模型；
- 脱敏后重新扫描，确认没有原文、映射表和敏感组合残留；
- 未知格式、解析失败和覆盖范围不明时默认阻断。

### 8.2 模型调用中

- 核对模型服务的数据留存和训练使用政策；
- 为不同数据等级配置不同模型、租户、密钥和网络出口；
- 限制 Context、Tool、Memory 和跨会话传播；
- 映射表不进入 system prompt、普通日志或工具参数；
- 防止模型输出或工具结果重新引入敏感指令和数据。

### 8.3 输出后

- 检测新生成的 PII、秘密和跨租户信息；
- 恢复 Token 前检查目的、收件人、字段权限和副作用风险；
- 对外发送、写入系统、发布和部署动作单独审批；
- 防止 Token 残留、原文残留和结构破坏。

### 8.4 Memory / Cache / Log

- Memory 写入需要来源、任务 scope、可信状态、过期、删除和回滚；
- Cache、Trace、错误日志、评测数据和反馈集默认不保存原文；
- 记录数据类别、策略版本和事件，而不是默认记录数据值；
- 映射表按任务隔离、加密和短期留存。

## 9. 评测指标

### 检测质量

- Entity detection precision / recall / F1；
- 通用实体和领域实体分别统计；
- Secret 漏检率；
- 敏感组合漏检率；
- 低置信度样本覆盖率。

### 变换质量

- 原文残留率；
- 错误遮蔽率；
- Token 残留率；
- Token 一致性；
- 错误恢复率；
- 映射表暴露率。

### 任务质量

- 文档结构保持率；
- 表格和公式正确率；
- 引用关系保持率；
- 摘要、分类和问答质量；
- 不同格式解析覆盖率和失败率。

### 全链路隐私

- 模型输入明文暴露率；
- 输出新生成 PII 率；
- Tool、Memory、Cache、Log、Trace 明文暴露率；
- 跨任务/跨租户关联率；
- 高风险数据人工审批覆盖率；
- 阻断率和误阻断率；
- 删除请求后的残留时间；
- 可验证删除率。

## 10. 第一版验收标准

第一版通用隐私层至少应满足：

1. 所有外部模型调用都经过统一 Privacy Gateway；
2. 高置信度凭证和密钥不会发送给外部模型；
3. PII 检测结果可解释、可定位、可审计；
4. Token 映射表不离开本地安全边界；
5. 输出恢复前必定经过复检和权限判断；
6. 解析失败、未知格式和覆盖范围不明默认阻断；
7. DOC、CSV、Excel 有独立基准集和回归测试；
8. 能统计漏检、误检、原文残留、Token 残留和任务质量；
9. Memory、Cache、Log、Trace 的明文暴露路径已经盘点；
10. 策略、检测器和映射服务可以独立升级。

## 11. 最终路线

```text
定义数据分类和外发边界
        ↓
统一 Entity Schema / Canonical Representation
        ↓
Regex + 校验器 + Secret Scanner
        ↓
通用 NER + 候选上下文模型
        ↓
allow / redact / tokenize / block / review
        ↓
任务级加密映射表和输出复检
        ↓
DOC / CSV / Excel 基准与回归
        ↓
PDF / OCR / Email / Code / Archive
        ↓
医疗 / 法律 / 财务 / HR 领域策略包
```

> 最重要的判断：先做可靠的通用隐私基础设施，不要先做“什么都能识别”的大模型。通用层的核心是统一实体模型、多层检测器、明确策略、安全 Token、输出复检和全链路审计。
