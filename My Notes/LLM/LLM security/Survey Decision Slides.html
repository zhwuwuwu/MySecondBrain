Security 做成 feature？

当本地类 Claw 可以读取文件、调用工具、访问网络并连续执行任务时，安全不再只是上线前的一次测试，而可能成为产品能力。

今天只讨论两个问题：
① 产品是否需要正式的 Security feature？
② 如果需要，第一阶段应先完善 Agent platform，还是先加入 safety 判断模型？

00 · TWO INVESTMENT PATHS

真正的优先级问题：Platform-first vs Model-first

PATH A · PLATFORM-FIRST

先把边界做实

投入权限、工具网关、workspace sandbox、网络、凭证、审批、trace 和回滚。

  • 即使模型判断错，也尽量做不到越权
  • 能力可解释、确定、可审计
  • 需要较多平台工程改造
PATH B · MODEL-FIRST

先增强风险判断

投入 SingGuard / SingGuard-NSFA 推理、策略、阈值和模型服务。

  • 更快覆盖复杂内容、意图偏离和动作风险
  • 可能复用已有 Agent 事件流
  • 需要验证误报、漏报、延迟和资源占用

本页不预设答案。后续内容将比较两条路径的风险覆盖、产品收益、性能代价、实施难度和可验证性，最后再提出建议。

01 · INTRODUCTION

为什么需要 Security feature？先分清五个基本概念

Agent 一旦产生外部副作用，产品需要保护的不只是回答质量，还包括模型、数据、凭证、工具、运行时和外部系统的机密性、完整性与可用性。

要问的问题

02 · PROBLEM DIMENSIONS

把“有风险”翻译成一条可验证链路

攻击面 → 技术 → 资产 → 影响 → 控制 → 证据

案例：网页诱导外传

  • 攻击面：网页 / 浏览器工具结果
  • 技术：indirect prompt injection
  • 资产：本地文件、工具权限、网络出口
  • 影响：秘密读取与外发
  • 控制：内容判断 + Policy Gateway + sandbox

上线后要看的指标

  • Unauthorized Action Rate
  • Secret Disclosure Rate
  • Denied-call Bypass Rate
  • Privilege Escalation Distance
  • Recovery / Rollback Success Rate

产品表达：我们不是要让 Agent 永远不犯错，而是要让高影响错误不会无审批地落地，并且可发现、可撤销、可复盘。

04 · ATTACK SPECTRUM

聊天模型的错误是“回答错”；Agent 的错误可能是“已经做完”

UNTRUSTED网页、文档、Skill、MCP 结果
CONTEXT内容进入 prompt / memory
PLAN目标被改变，规划继续
TOOLShell、文件、网络、API
EFFECT读写、外传、部署、持久化

攻击链不是单点问题

OpenAI–Hugging Face 研究材料展示了高能力 Agent、弱约束 Harness、代码执行工具、数据管线、凭证和网络边界如何组合成跨边界攻击链。

产品要控制的是组合能力

不只检查“这句话危险吗”，还要检查谁在做、对什么资源、用什么参数、会产生什么副作用，以及发生后如何恢复。

DEFENSE PRINCIPLE判断不是阻断
05 · DEFENSE LAYERS

模型可以说“看起来危险”，系统必须决定“能不能执行”

DETECT

判断

模型、规则、红队和人工分析输入、计划、工具和 trace。

AUTHORIZE

授权

结合用户、任务、资源、时间和副作用判断是否被允许。

ENFORCE

阻断

Policy Gateway、OS、网络、容器和工具参数做确定性限制。

RECOVER

恢复

吊销凭证、隔离 runtime、回滚状态、保留证据。

User goal
UNSAFE ACTION JUDGE把“危险”拆成可判断的对象
06 · BASIC DEFINITION

安全判断必须同时回答：想做什么、被允许什么、实际发生什么

01

Intent

Agent 的计划和工具参数是否服务于用户任务？

“总结项目”不应该自动扩展成读密钥、访问生产库或发邮件。

02

Authorization

当前用户、任务、资源和时间窗是否真的授权？

用户目标不是权限授予，读取不等于删除，项目 A 不等于项目 B。

03

Observed Effect

实际文件、网络、凭证、memory 和外部副作用是什么？

不能只看 Agent 的自然语言解释，要看完整参数和真实 trace。

Unsafe Action 维度

授权越界、意图偏离、过大能力、秘密泄露、动作完整性、外部副作用、运行时突破、持久化传播、资源滥用。

为什么不是一个 classifier？

单条动作可能低风险，连续动作可能形成 secret → context → tool → external API 的完整外传链；必须结合状态和历史 trace。

09 · BENEFITS

投入安全，换来的是“敢用、能交付、出事可恢复”

C-END USER

对本地用户

  • 本地文件、memory 和凭证有明确边界
  • 删除、外发、部署可预览、确认或回滚
  • 恶意网页、Skill、MCP 不会直接获得无限能力
  • 拒绝时能解释原因，降低用户恐惧成本
OEM / PLATFORM

对 OEM 与产品方

  • 降低数据泄露、越权和供应链事故概率
  • 有策略、日志和版本化证据，减少售后定位成本
  • 支持 observe → enforce 渐进式上线
  • 可以按 SKU 提供不同安全等级，形成差异化

不要承诺错误收益：安全层不会自动提升普通回答正确性；它的收益是降低高影响错误的概率与损失，提高发现、止损和恢复能力。

INTEGRATION模型判断 → 系统授权 → 安全执行
11-2 · INTEGRATION PLAN

推荐 pipeline：两层模型，中间必须有确定性策略

用户输入 / 外部网页 / 图片 ↓ SingGuard：多模态内容与 policy 判断（有多模态需求时） ↓ Agent Planner ↓ NSFA：计划、工具名、完整参数、结果和外发内容 ↓ Policy Gateway：用户 / 任务 / 路径 / 域名 / 权限 / 副作用 ↓ 人工审批：删除、外发、部署、改权限、读取凭证 ↓ Sandbox：文件、进程、网络、凭证隔离 ↓ 执行 + Audit Trace + Recovery

NSFA 两种方式

Generative Reasoning：离线审计、复杂案例，接近 LLM-as-a-Judge。
Real-Time Classification：分类头直接输出概率，适合工具调用前的低延迟检查。

模型不做的事

不负责最终授权，不替代文件权限、API authorization、网络隔离、sandbox、源码扫描、依赖扫描和恢复系统。

PERFORMANCE BUDGET用本地 SKU 测，不用论文 SLA
11-2 · PERFORMANCE BENCHMARK

会增加成本，但可以把成本放在高风险路径上

延迟
P50 / P95

每次同步模型判断都会增加等待；NSFA 公开约 45–57 ms/sample 是 A100 条件。

质量
Precision / Recall

护栏不应改写正常回答；误报会增加拒绝/审批，漏报依然存在。

资源
RAM / VRAM / CPU

模型加载、KV cache、图片编码和并发会占用本地资源。

可用性
Timeout / Fallback

模型超时或 OOM 会影响体验，必须有观测模式和按动作风险设计的 fallback。

11-2 · PILOT PLAN

第一阶段不是上线阻断，而是回答四个问题

01

真实风险是什么？

收集用户请求、计划、工具、结果、memory 写入和外部副作用；按风险域标注。

02

模型判断准不准？

用合法任务 + 攻击样本测 precision、recall、F1、漏报和误报。

03

本地代价多大？

NSFA 0.8B/2B/4B、SingGuard 按需求，在不同内存 SKU 测延迟、峰值资源和功耗。

04

哪些动作值得阻断？

定义高影响动作：读凭证、外传、删除、部署、改权限默认拒绝或人工审批。

WEEK 1基线与 trace
WEEK 2–3离线审计与样本
WEEK 4–5Shadow mode
WEEK 6有限 enforce 决策

上线门槛：不是“模型安全分数高”，而是“高影响动作的未授权比例下降，合法任务体验和本地资源仍在预算内”。

PLATFORM WORK模型之外，必须把边界做实
12 · PLATFORM STRATEGY

四类平台建设，让模型判断真正有地方落地

Shell / Workspace

命令和参数 allowlist；workspace 外文件默认拒绝；限制删除、安装、权限修改、子进程和网络上传；隔离宿主机凭证。

MCP / Skill 供应链

记录来源、版本、hash、权限和依赖；安装前扫描；工具结果视为不可信 observation；高权限 Skill 可审批、签名和撤销。

Memory / RAG

区分用户明确保存和 Agent 自动写入；写入前检查恶意指令和 secret；按用户/任务隔离；保留来源、版本和回滚。

Identity / Recovery

短期最小权限凭证；secret 不进入不必要上下文；异常时 kill Agent、吊销 token、隔离 workspace、重建 runtime。

思路 1（模型护栏）负责“看起来危险”；思路 2（平台控制）负责“是否授权、能不能做到、发生后如何止损”。两者不能互相替代。
FINAL RECOMMENDATION把研究转成可验证的产品决策
00 · FINAL DECISION

建议做，但先做“可控 Agent”而不是“更多模型”

必须

平台安全底座

权限、sandbox、网络、凭证、trace、审批、恢复。

优先试点

NSFA 0.8B / 2B

先离线审计，再 shadow mode，再高影响动作有限阻断。

按需启用

SingGuard

产品有图片、截图、网页图文时，补充多模态内容安全。

请批准：4–6 周 pilot，并以真实本地 SKU benchmark 作为是否产品化的依据。若应用纯文本且资源受限，不要为了“两个模型都上”而增加同步路径成本。

最终目标：用户敢用，OEM 敢交付，产品出事能解释、能止损、能恢复。
