00 · TWO INVESTMENT PATHS

真正的优先级问题：Platform-first vs Model-first

PATH A · PLATFORM-FIRST

先把边界做实

投入权限、工具网关、workspace sandbox、网络、凭证、审批、trace 和回滚。

  • 即使模型判断错，也尽量做不到越权
  • 能力可解释、确定、可审计
  • 需要较多平台工程改造
PATH B · MODEL-FIRST

先增强风险判断

投入 SingGuard / SingGuard-NSFA 推理、策略、阈值和模型服务。

  • 更快覆盖复杂内容、意图偏离和动作风险
  • 可能复用已有 Agent 事件流
  • 需要验证误报、漏报、延迟和资源占用

本页不预设答案。后续内容将比较两条路径的风险覆盖、产品收益、性能代价、实施难度和可验证性，最后再提出建议。

02 · PROBLEM DIMENSIONS

把“有风险”翻译成一条可验证链路

攻击面 → 技术 → 资产 → 影响 → 控制 → 证据

案例：网页诱导外传

  • 攻击面：网页 / 浏览器工具结果
  • 技术：indirect prompt injection
  • 资产：本地文件、工具权限、网络出口
  • 影响：秘密读取与外发
  • 控制：内容判断 + Policy Gateway + sandbox

上线后要看的指标

  • Unauthorized Action Rate
  • Secret Disclosure Rate
  • Denied-call Bypass Rate
  • Privilege Escalation Distance
  • Recovery / Rollback Success Rate

产品表达：我们不是要让 Agent 永远不犯错，而是要让高影响错误不会无审批地落地，并且可发现、可撤销、可复盘。

MODEL VS AGENT从模型生命周期到 Agent 运行时
03 · MODEL SECURITY & AGENT SECURITY

从模型拒答到副作用控制

MODEL SECURITY

模型生命周期安全

主要关注数据、训练和推理 API，例如：

  • 数据获取、清洗、标注、授权和隐私；
  • 预训练、微调、对齐和评测配置；
  • 权重、checkpoint、量化文件和依赖供应链；
  • 推理 API、认证、限流、日志和多租户隔离；
  • 模型行为：越狱、Prompt Injection 和拒答绕过。
典型控制：数据 provenance、依赖 hash、访问控制。
AGENT SECURITY

Agent 运行时安全

Agent 在 Model Security 之外增加了：

  • Harness / Orchestrator 和任务目标；
  • Prompt/context 组装；
  • Memory/RAG/状态持久化；
  • Tool/API/MCP/connectors；
  • 身份、权限、审批和用户确认；
  • Sandbox、宿主机、网络和凭证；
  • 监控、回滚和事件响应。
本地类 Claw 的主要安全重点是 Agent Security，而不是只做模型拒答率优化。

Runtime Enforcement & Recovery

所有高影响动作进入统一网关。贯穿完整 trace，支持异常检测、隔离 workspace、吊销凭证、撤销可逆动作与事后复盘；不可逆动作默认提高审批级别，最终结果只能是 Allow / Block / Approval。

Observe before Enforce

先以 observe 模式记录会被阻断的动作，校准误报和体验；再对高置信策略启用 enforce。策略按风险分级上线，而非一次性全部拦截。

UNSAFE ACTION JUDGE把“危险”拆成可判断的对象
06 · BASIC DEFINITION

安全判断必须同时回答：想做什么、被允许什么、实际发生什么

01

Intent

Agent 的计划和工具参数是否服务于用户任务？

“总结项目”不应该自动扩展成读密钥、访问生产库或发邮件。

02

Authorization

当前用户、任务、资源和时间窗是否真的授权？

用户目标不是权限授予，读取不等于删除，项目 A 不等于项目 B。

03

Observed Effect

实际文件、网络、凭证、memory 和外部副作用是什么？

不能只看 Agent 的自然语言解释，要看完整参数和真实 trace。

Unsafe Action 维度

授权越界、意图偏离、过大能力、秘密泄露、动作完整性、外部副作用、运行时突破、持久化传播、资源滥用。

为什么不是一个 classifier？

单条动作可能低风险，连续动作可能形成 secret → context → tool → external API 的完整外传链；必须结合状态和历史 trace。

DIMENSIONS不是简单的 Prompt + Classifier
07 · AGENT SECURITY DIMENSIONS

Agent 安全维度拆解

1. Authorization Boundary

授权越界：允许读却删除、访问项目 B、普通用户调用管理员 API、查询变写入。

2. Intent Alignment

意图偏离：动作偏离任务或擅自增加目标。适合模型或人工复核，不能单决权限。

3. Excessive Agency

能力过大：任意 Shell/SQL；工具权限跨越；高影响动作无需审批回滚。

4. Confidentiality

机密性违规：外传机密数据。无显式 declassification（解密流）应拒绝数据流。

5. Integrity

完整性违规：目标、参数错误，改错文件、付错款，或者把不可信命令作为参数。

6. External Side Effect

外部副作用：动作的单步或累积影响。删除、支付、发邮件、公开发布等通常需审批。

7. Runtime Boundary

运行时突破：访问 workspace 外文件、宿主机凭证。须由 OS 和 runtime 强制执行。

8. Persistence

持久化传播：恶意内容进入长期 memory、RAG、其他 Agent、配置或下一会话。

9. Availability

资源滥用：无限循环、retry storm、工具调用风暴、token耗尽、大规模云资源操作。

Unsafe Action 的统一判断输入：动作类型 + 目标资源 + 完整参数 + 当前状态 + 用户授权 + 历史动作 + 预计副作用

* 安全判定决不能只把一段自然语言回答交给一个分类器。

WHY INVEST安全是产品可信度，不只是合规成本
09 · BENEFITS

投入安全，换来的是“敢用、能交付、出事可恢复”

C-END USER

对本地部署类 Claw 应用的 C 端用户

  • 降低恐惧成本：用户知道 Agent 不会因为一段网页内容就随意读取和外发本地文件；
  • 保护个人资产：本地文档、照片、浏览器会话、SSH key、云凭证和长期 memory 有明确边界；
  • 高影响动作可控：删除、发送、部署和改权限能够预览、确认或回滚；
  • 更少隐形数据外流：网络出口和工具参数受控；
  • 问题可解释：发生拒绝时能够说明是哪个策略、哪个资源和哪个动作触发。
OEM / PLATFORM

对部署本地应用的 OEM

  • 降低事故成本：减少数据泄露、越权、恶意 Skill/MCP 和供应链事件；
  • 提升交付可信度：安全策略、审计日志、版本化配置可以成为产品合同的一部分；
  • 减少售后定位成本：有完整 trace，可以区分模型问题、工具问题和平台权限问题；
  • 支持产品分层：普通 SKU 使用轻量规则，高级 SKU 提供本地安全模型和更强审计；
  • 形成差异化：将“可控 Agent”作为 OEM 交付能力，而不是只比较模型回答效果。

需要避免的错误预期：

  • 安全层不会自动提升模型事实正确性；
  • 模型护栏不会替代源码和依赖漏洞扫描；
  • 安全能力会有误报、漏报和资源成本；
  • 一次 benchmark 不能证明所有用户场景都安全。

MODEL-BASED JUDGMENT使用模型同步判断多种风险类型
11-0 · OVERVIEW

思路 1：使用模型同步判断多种风险类型

模型一：SingGuard

策略可适配的多模态 LLM 安全护栏。分为两级模型架构的一部分，主要负责多模态输入和内容的安全性。

模型二：SingGuard-NSFA

面向 Agent 操作风险的文本护栏框架。纯文本、工具型本地 Agent 优先评估。专注于操作和执行时的意图、动作等风险判断。

COMPARISON模型能力对比
11-1 · COMPLEMENTARY RELATIONSHIP

SingGuard & SingGuard-NSFA 综合对比

SingGuard

1. 模型定位
策略可适配的多模态 LLM 安全护栏。
2. 功能覆盖
判断文本、图片、图文是否违反 policy；覆盖 Prompt Injection、越狱、敏感内容与自定义业务政策违规。
3. 适配输入输出
输入：文本、图片、图文、自然语言 policy。输出：safe/unsafe、匹配风险类别、策略相关分析。
4. 基础模型和规模
Qwen3-VL，2B/4B/8B，Apache 2.0。
5. 训练架构
统一文本/多模态安全数据 SFT；论文报告用 Fast-Slow Decoupled DAPO 优化动态推理。完整训练集来源、规模和配比未完全公开。
6. 风险体系和安全 Benchmark
SingGuard-Bench 约 56,340 样本。8B 报告：Image Safety F1 0.903、Text Query F1 0.874、Multimodal Safety F1 0.877、Text Response F1 0.893；Dynamic Rule（2,000 样本）policy-following accuracy 0.7415。
7. 部署 Benchmark / 注意事项
多模态模型需要图像处理和更高内存/显存；公开资料没有可直接承诺的本地端到端 SLA，应按设备 SKU 测模型加载、图片分辨率、上下文长度、并发和 P95 延迟。
8. 类 Claw 集成位置
用户输入/网页/图片进入 Agent 前，以及 Agent 输出/待展示内容返回用户前。可检查工具调用的文字化描述。

SingGuard-NSFA

1. 模型定位
面向 Agent 操作风险的文本护栏框架。
2. 功能覆盖
判断 Prompt Injection/Jailbreak、恶意代码与网络攻击、敏感信息窃取/外传、危险操作/工具滥用、资源滥用与危险动作生成。
3. 适配输入输出
输入：用户请求、外部内容、计划、工具名/完整参数、工具结果、最终输出的文本化表示；建议区分 untrusted_input 与 untrusted_output。输出：风险类别、生成式风险分析或实时分类风险概率。
4. 基础模型和规模
Qwen3.5-Base，0.8B/2B/4B/9B，Apache 2.0。
5. 训练架构
风险分析数据 SFT；冻结 SFT 后骨干，为不同风险域训练轻量 MLP 分类头；新增风险可仅训练新分类头。
6. 风险体系和安全 Benchmark
7 个一级域、28 个二级风险、185 个三级变体；93,000+ purpose-built multilingual samples（133 种语言）、3,435 cross-source samples。四种规模 purpose-built 均 ≥94% F1；9B cross-source F1 91.29%；竞品对比高 6–12 个 F1 百分点。
7. 部署 Benchmark / 注意事项
Real-Time Classification 在 A100 条件约 45–57 ms/sample；仅作参考，不是本地设备 SLA。本地需测模型加载内存、CPU/GPU、并发、上下文长度、P50/P95 延迟和超时行为。
8. 类 Claw 集成位置
用户输入检查、Agent 计划与工具参数检查、结果与外发内容检查；之后必须进入确定性 Policy Gateway 决定执行或拒绝。
共同边界：两个模型都不替代确定性授权和执行控制；均不负责真实文件权限、API 授权、网络隔离、sandbox、源码/依赖漏洞扫描或恢复系统。
INTEGRATION模式、集成与部署考虑
11-2 · NSFA MODES & INTEGRATION

NSFA 运行模式与运行时集成链

NSFA 应作为 Agent runtime 的风险判断器 接入，而不是替代工具网关或直接执行动作。建议由 Orchestrator 在每个可观测事件处组装结构化上下文调用 NSFA；再把风险结果与用户身份、Security Envelope 和确定性规则一起交给 Policy Gateway 决策。

生命周期数据流

用户 / 外部内容 ↓ [输入检查] Agent Planner ↓ [计划检查] 工具调用提案（tool + 完整参数） ↓ [动作前检查] Policy Gateway（身份+scope+风险+确定性规则） ├─ allow → Sandbox / 工具执行 ├─ approval → 用户确认后执行 └─ block → 返回可解释拒绝 ↓ 工具结果 / 外发内容 / memory 写入 ↓ [结果、外发与持久化检查] Audit Trace / 恢复

调用契约（结构化上下文）

每次调用至少保留以下结构，而不是只传一段 prompt：

<untrusted_input>用户请求、网页、文档等</untrusted_input> <untrusted_output>Agent 计划、工具调用、结果等</untrusted_output> task / intent / user_identity / session_id tool_name / full_parameters / target_resource security_envelope / prior_actions / observed_effect / expected_side_effect

NSFA 输出风险类别/概率/生成式分析（仅作信号与审计证据）。最终授权由 Policy Gateway 做出。

建议接入的五个阶段

阶段 应送入 NSFA 的事件 重点判断 结果如何使用
1. 输入与上下文进入 用户请求、网页/文档/Skill/MCP 工具结果、检索结果 Prompt Injection、Jailbreak、恶意代码/网络攻击指令、秘密诱导 标记风险与 provenance；高风险不能直变 Agent 指令，可降权/隔离/重述。
2. 计划生成后 用户目标、当前 Security Envelope、Agent plan、拟调用工具集合 意图偏离、隐式扩权、过大自治、跨任务目标传播 计划不通过时要求缩小 scope、移除高风险步骤或转人工确认。
3. 每次工具调用前 工具名、完整参数、目标路径/账户、当前身份、历史动作、预计副作用 工具滥用、敏感数据外传、危险操作、SSRF、资源滥用 将风险送入 Policy Gateway，结合 allowlist/权限产出 allow / approval / block。
4. 工具结果写入后 工具 stdout/stderr、文件实际 effect、memory 写入候选、重试链 工具结果注入、秘密回流 context、memory poisoning、异常重试 结果按可信度标记；阻止高风险写入长期 memory；触发终止/收紧 scope。
5. 最终输出与外发前 面向用户的回答、邮件/消息/API payload、附件与接收方 敏感信息泄露、危险动作说明被再次执行、错误目的地、不可逆外发 输出脱敏或改写；外部发送等高影响动作仍由 Policy Gateway/用户决定。

两种模式如何分工

  • Real-Time Classification：放在第 1、3、4、5 阶段的在线路径，适合高频、时延敏感的输入、工具调用、结果与外发检查；应设置按动作等级的超时预算。
  • Generative Reasoning：用于第 2 阶段的复杂计划复核，以及离线 trace 审计、事件调查、人工复核和策略调优；不应成为所有低风险工具调用的同步前置依赖。

失效、降级与可恢复性

  • 不得默认放行：NSFA 超时、崩溃时，不得默认扩大权限或放行高影响动作；继续执行由已有策略决定。
  • 区分降级策略：低影响、只读且被 allowlist 覆盖动作可记录风险并继续；读取 secret、外部上传、删除等保持 block/approval。
  • Trace 闭环：所有请求、决策与降级原因写入 trace，支持复盘回滚。

部署考虑：0.8B/2B 可作为本地 pilot 候选规模。需在实际设备 SKU 上测模型加载内存、CPU/GPU、并发、上下文长度、P50/P95 延迟和超时行为。A100 的 45–57 ms/sample 只能作为参考，不是本地设备 SLA。

PILOT PLAN4 个阶段及验收指标
11-3 · PILOT PLAN & METRICS

试点计划与验收指标

阶段 0：建立基线（1 周）

记录现有 Agent 的用户请求、计划、工具调用、结果、memory 写入和外部副作用等 trace；统计普通任务的 P50/P95 延迟、回答成功率、工具成功率、资源等；标注高影响动作和敏感资源。

阶段 1：离线审计与数据集（1-2 周）

用 NSFA Generative Reasoning 审计历史 trace；构造合法任务、Prompt Injection、越权读写、secret 外传、MCP/Skill 污染、资源滥用样本；对每条样本记录人工标签和预期处理。

阶段 2：Shadow Mode（1-2 周）

NSFA 在线分类接在工具调用前，但不改变执行结果；SingGuard 接在多模态出入口；记录模型判断、规则判断与人工标签差异；测模型大小与设备 SKU 的内存、速度和准确率曲线。

阶段 3：有限 Enforce（1 周）

只阻断高置信度、高影响、不可逆的动作（如读凭证、外传、删除、部署等默认拒绝或审批）；明确模型超时、模型崩溃和 Policy Gateway 不可用时的 fallback。

维度 试点验收指标
安全 Secret Disclosure Rate、Unauthorized Action Rate、Denied-call Bypass Rate
判断质量 Precision、Recall、F1、误报率、漏报率、按风险域拆分的混淆矩阵
体验 Agent 成功率、合法任务拒绝率、用户确认率、回答正确性变化
性能 额外 P50/P95 延迟、模型加载时间、峰值内存/显存、CPU/GPU、功耗
稳定性 timeout、fallback、重试风暴、模型崩溃、断网和低资源场景
恢复 吊销凭证、隔离运行时、回滚文件/状态、保留证据的成功率

12 · PLATFORM STRATEGY

执行层平台控制待实施事项（按控制类型 × 阶段分类）

需先纠正的三个假设

  • Trajectory ≠ 完整审计：不能证明覆盖网络/审批/内存/文件，无防篡改留存。
  • Workspace/Sandbox ≠ 隔离闭环：容器内仍可能外发数据或产生副作用。
  • Shell Guard ≠ 命令安全闭环：缺乏危险命令、混淆、网络外发的统一 policy 引擎。

分类维度说明

  • 类型：Observe(记录), Guardrail(脱敏/门控), Refuse(阻断), Execution(底座)
  • 阶段：inbound, prompt, pre_tool, post_tool, memory_write, outbound, cross
  • 优先级：P0(无底座不开放自动执行), P1(收窄风险), P2(规模化治理与可验证)
P0 Execution cross_phase

1. 策略决策引擎与骨架

统一 SecurityAction schema 与决策引擎；Policy 优先级与作用域规则；Fail-closed 默认策略；集成控制面。

P0 Refuse pre_tool

2. 危险动作执行护栏

Plugin自我防护；拦截危险命令、破坏性写入、网络出口/SSRF；限制资源滥用；证明阻断无副作用。

P0 Guardrail pre/outbound

3. 审批与最终输出边界

接入审批并持久化关联；响应/artifact 统一脱敏(sanitizer)；凭证/敏感信息命中默认 enforce。

P0/P2 Execution cross_phase

4. 审计事件与留存治理

可验证防篡改的证据；事件关联 policy decision；受限 ACL 与不可变存储，默认不留原文/密钥。

P1 Observe/Guard in/prompt/post

5. 不可信输入与结果

把外部内容与工具结果当独立不可信边界；风险检测；上下文附加；结果注入检测并在进 context 前处理。

P1 Observe/Guard memory_write

6. Memory 写入治理

防止低可信内容变未来高可信指令；来源/污染检查(先 observe 再 enforce)；缩短 PII 映射 TTL。

P1/P2 Obs/Guard/Ref cross_phase

7. 观测与选择性 Enforce

真实数据校准后逐条收紧；高置信度规则从 observe 升为 enforce；单条规则可独立回滚。

P1 Execution cross_phase

8. 安全测试与验证矩阵

证明阻断生效、无副作用；对抗性测试夹具（混淆、投毒等）；覆盖各边界的负向集成测试。

与思路 1（模型护栏）的分工：模型只产出风险信号，本节的策略网关与审计闭环是唯一能把信号转成 allow / observe / redact / require_approval / block 并留下证据的执行层。两者不可互相替代。
