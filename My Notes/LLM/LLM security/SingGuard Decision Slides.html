两个护栏模型
要不要进类 Claw？

给 Senior Manager 的决策简报：SingGuard 解决“内容是否安全”，SingGuard-NSFA 解决“Agent 是否准备做危险的事”。

建议：不建议一开始同时全量上线。先以 NSFA 0.8B/2B 做运行时试点；只有当产品有图片/多模态内容安全需求时，再加入 SingGuard。

01 · BUSINESS CONTEXT02 / 10

类 Claw 的风险，不止是“回答有害”

Confidentiality

秘密泄露

Agent 读取 .env、SSH key、云凭证，或把工具结果外发。

Integrity

动作越权

用户只要求总结，Agent 却修改文件、安装依赖、部署或发送消息。

Availability

资源滥用

无限循环、重试风暴、任意网络访问或高成本工具调用。

untrusted content → context → plan → tool call → external effect → memory / trace

模型护栏的价值：在“内容进入 Agent”与“动作落地”之间增加一个风险判断点；但真实阻断仍依赖 Policy Gateway、权限和 Sandbox。

维度SingGuardSingGuard-NSFA

选择逻辑：纯文本个人 Agent → 先 NSFA；有网页截图、图片理解或图文交互 → SingGuard 作为补充。

03 · SINGGUARD04 / 10

SingGuard：策略条件化的多模态 Judge

内容 + 当前 policy
→ safe / unsafe + 风险类别

同一内容可以在不同产品政策下得到不同判断；新规则通常作为运行时自然语言输入，不必为每条规则重训。

输入 / 输出

  • 输入：文本、图片、图文、当前安全政策
  • 输出：整体安全判断、匹配类别、策略相关分析
  • 公开规模：Qwen3-VL 2B / 4B / 8B
  • 许可证：Apache 2.0
INPUT用户输入 / 网页 / 图片
POLICY业务安全规则
JUDGESingGuard
OUTPUT放行 / 复核 / 拦截信号

它是 LLM-as-a-Judge 风格的生成式判断，但“拦截”必须由应用策略层执行。

04 · SINGGUARD-NSFA05 / 10

NSFA：面向 Agent 行为的双路径护栏

Offline

Generative Reasoning

生成风险分析和结构化判断，适合历史 trace、复杂案例、事件调查和人工复核。它更接近传统 LLM-as-a-Judge。

Online

Real-Time Classification

冻结骨干 + 多个轻量分类头，直接输出风险概率，不需要先生成一段解释再解析；适合工具调用前的低延迟检查。

05 · EVIDENCE06 / 10

公开证据：能力强，但不要把 benchmark 当安全保证

SingGuard

基座：Qwen3-VL 2B/4B/8B
训练：SFT + 论文报告的 Fast-Slow Decoupled DAPO
评测：SingGuard-Bench，约 56,340 样本

8B F1：Image .903 · Text Query .874 · Multilingual Query .899 · Multimodal .877 · Text Response .893 · Multilingual Response .893；动态策略准确率 .7415。

SingGuard-NSFA

基座：Qwen3.5-Base 0.8B/2B/4B/9B
训练：风险分析 SFT + 冻结骨干上的 MLP 分类头
评测：93K+ / 133 语言 + 3,435 cross-source

purpose-built：均 ≥94% F1；cross-source：9B 为 91.29% F1；相对竞品约 +6–12 F1 点。

数据集/底层测试集的公开范围、底层硬件和跨域分布仍需在 pilot 中复现；论文指标不等于你们应用的 precision/recall。

06 · INTEGRATION07 / 10

推荐架构：模型判断，策略执行

用户输入 / 网页 / 图片
　　　　↓
SingGuard：内容与多模态风险
　　　　↓
Agent Planner
　　　　↓
NSFA：计划、工具名、完整参数、结果
　　　　↓
确定性 Policy Gateway：用户 / 任务 / 路径 / 域名 / 权限
　　　　↓
人工审批（高影响动作）
　　　　↓
Sandbox：文件、进程、网络、凭证隔离
　　　　↓
执行 + 审计 trace

工具调用前

把 user_intent、allowed_paths、tool、完整 arguments 序列化给 NSFA；实时分类给风险信号，Policy Gateway 决定放行/拒绝/审批。

结果与外发前

NSFA 检查工具结果和 Agent 输出；SingGuard 检查图片、网页和多模态内容；禁止模型结果直接获得授权。

08 · VALUE & LIMITS09 / 10

它们能降低什么风险？不能解决什么？

可以起到的作用

  • 发现 Prompt Injection 与越狱信号
  • 识别读取凭证、危险 Shell、外传等工具风险
  • 在 Agent 输出到达用户前做泄露检查
  • 对历史 trace 做批量审计与风险聚类
  • 给高风险动作提供解释、阈值和人工复核依据

不能单独解决

  • SQL 注入、SSRF、依赖漏洞和源码缺陷
  • API 越权、真实文件权限和身份授权
  • 容器逃逸、云 metadata、网络隔离
  • 模型漏判/误判后的确定性安全保证
  • 跨多步攻击链的完整因果与恢复控制

核心边界：模型输出是风险信号，不是“允许执行”的事实。

09 · RECOMMENDATION10 / 10

建议批准一个小范围 pilot，而不是直接双模型全量上线

Phase 1 · 4–6 周

  • NSFA 0.8B/2B 离线审计历史 trace
  • 建立 50–100 条真实攻击/误报样本
  • 测 precision、recall、漏报、延迟、显存
  • 只对高危工具调用做 shadow mode

Phase 2 · 通过门槛后

  • NSFA 接入工具调用前风险判断
  • Policy Gateway 执行确定性拒绝
  • 若有图片/图文入口，再加入 SingGuard
  • 持续红队：注入、外传、越权、资源滥用

管理层决策建议：批准 NSFA pilot；SingGuard 作为“有多模态需求才启用”的可选项。若应用目前只有纯文本输入输出，同时采购两者的边际收益有限。
