Executive brief · LLM & Agent Security

让个人助手
敢于行动，也不越界。

面向 Claw 类 Agent 平台的安全全景与产品切入建议。核心判断：安全不是给模型再加一个拒答 prompt，而是保护数据、凭证、工具、运行时状态和真实世界副作用。

面向：高级经理 / 产品与安全负责人对象：个人助手 / Skills / MCP / Memory基于：LLM 与 Agent Security 总览
01 / THE MAP

先把“安全”
放回正确的地图

管理层不需要记住所有攻击名词，需要知道每个问题落在哪个边界、影响什么资产、最终由谁来拦。

DATA SUBJECT

Privacy

个人或敏感信息是否被过度收集、推断、记忆、跨租户使用或披露。

C / I / A

Security

对抗者或未授权路径是否破坏机密性、完整性、可用性，或扩大 Agent 权限。

HARM

Safety

即使没有攻击者，系统是否会因错误决策和自动化造成不可接受的伤害。

UNDER STRESS

Robustness

面对扰动、异常和对抗输入时，能力与安全性质是否仍在可接受范围。

Reliability 是另一条轴：它问“系统能否按规格稳定工作并恢复”，不是安全本身。一个系统可能可靠地执行过大的权限，也可能安全但每次都拒绝合法任务。

HOW THEY GET IN

Prompt injection

不可信内容被模型误认为指令，改变计划或工具选择。它是攻击技术，不等于输出安全。

WHAT IT DOES

Agent 行为

越权读写、危险工具、提权、外传、部署、删除、资源滥用。最终问题是授权与副作用。

WHAT IT READS

Memory / Skill / MCP

长期记忆、Skill 包、工具描述和返回值都是可被污染或篡改的执行输入。

03 / RISK TAXONOMY

同一个风险，
要用多个维度描述

“Prompt injection”“MCP 扫描”“恶意行为”不在同一个分类层级。把攻击面、技术、行为、影响和控制混在一起，会导致产品边界和指标失真。

管理层记忆法：攻击面是“从哪里进来”，攻击技术是“怎么骗/怎么打”，Agent 行为是“做了什么”，影响是“什么受损”，控制是“在哪里查、拦和恢复”。

影响 / Impact哪个资产或性质受损？机密性、完整性、可用性、隐私、安全性、可靠性、费用和业务状态按影响分级审批、告警和恢复
控制 / Control在哪个位置检测、授权、阻断、恢复？Classifier、Policy Engine、Capability Gateway、Approval、Sandbox、IR将判断与确定性执行控制分离
INPUT / CONTEXT

说了什么？

恶意或有害输出、越狱、Prompt Injection。输出安全关注内容，注入关注控制流被改变。

ACTION / AUTH

做了什么？

Unsafe Action、Excessive Agency、权限滥用。最终要对照任务、资源、用户和时间窗口判断授权。

ASSET / SUPPLY CHAIN

依赖可信吗？

Skill、MCP Server、依赖和工具描述是供应链与连接器攻击面；扫描是保障控制，不是攻击类型。

04 / CONTROL PLANES

防御体系不是一堵墙，
而是分层控制平面

每个控制平面解决不同问题：模型判断可以做风险理解，但真正保护系统的，是授权、运行时、网络、身份和恢复等可验证边界。

Defense-in-depth · 从意图到恢复的六层平面
01 · Intent plane任务目标、范围、资源、期限、用户确认；把“用户说了什么”变成可验证 scope绑定意图
02 · Context plane指令、观察、Memory、RAG、Skill 和 Tool Result 的来源、可信度、隔离与拼装隔离数据
03 · Policy plane确定性规则、风险分级、能力网关、最小权限、审批和下游 complete mediation决定能否做
04 · Execution planeTool/API/MCP、文件、进程、浏览器、凭证和网络出口的逐调用限制限制怎么做
05 · Runtime planeSandbox、容器/VM、非 root、资源/时间限制、短期凭证和 egress allowlist限制最坏结果
06 · Evidence planeTrace、告警、凭证吊销、环境重建、状态回滚、事后复盘和策略回归发现并恢复

判断层 ≠ 执行层

LLM judge、Guardrail Model 和风险分类器适合解释意图、识别异常、给出风险信号；它们不应单独决定是否读取密钥、删除文件、部署代码或发送外部请求。

扫描层 ≠ 阻断层

MCP/Skill 扫描可以发现来源、权限、依赖和行为风险；发现后还必须接入 Policy Engine、审批、Sandbox 和网络控制，否则只是报告。

05 / ACTION JUDGMENT

判断 Agent 是否危险，
先分清三件事

Agent 的自然语言解释不是事实证据。平台必须分别记录它想做什么、被允许做什么，以及实际发生了什么。

INTENT

它想做什么？

语义问题：计划和工具参数是否服务于用户目标？例如“总结项目”却开始安装依赖、访问生产库或发邮件。

AUTHORIZATION

它被允许做什么？

策略问题：用户目标不是权限授予。“总结项目”不自动授权读取 `.env`、访问外网、修改文件或访问另一个项目。

OBSERVED EFFECT

它实际做了什么？

执行/审计问题：观察完整工具调用、参数、文件/网络访问、凭证使用、Memory 写入、重试链和最终副作用。

Decision gate · 只有三者对齐才可自动放行
用户目标总结、查找、修改、发送？
绑定 Scope用户 / 任务 / 资源 / 时间
不可信规划器LLM 可以提出计划
能力网关确定性策略 + 审批
Observed Effect实际结果与审计证据
核心原则：模型可以参与理解意图和风险评估，但不能单独承担权限控制、凭证保护、沙箱隔离和网络边界。
06 / UNSAFE ACTION

“不安全行为”
不是一个二分类

把 Agent 行为拆成可观测维度，才能决定是拦截、审批、降权、记录还是允许。

拆解维度判断问题示例建议控制
授权越界是否超出用户、租户、任务或工具授权？允许读却删除；项目 A 访问项目 B；普通用户调用管理员 API下游每次鉴权、能力 token、scope 绑定
意图偏离动作是否仍服务于用户目标，还是擅自增加目标？“总结项目”变成安装依赖、修改代码、发送邮件意图审查、计划解释、人工确认
能力过大工具功能、权限和自主程度是否超过必要范围？任意 shell、任意 URL、读工具持有写权限、高影响动作无需审批最小工具、最小权限、风险分级
数据机密性是否读取、推断、输出或外传未授权数据？`.env`、SSH key、云凭证、跨租户数据进入上下文或 API 参数数据流标记、secret redaction、显式 declassification
动作完整性动作类型允许，但目标、参数或内容是否错误？改错文件、给错账户付款、部署未经审批代码完整参数预览、目标绑定、状态检查、回滚
外部副作用是否不可逆、高影响、对外、删除、支付、部署或发布？发邮件、转账、改权限、公开发布、生产部署审批、双人确认、幂等、撤销和回滚
运行时突破是否越出 workspace、宿主机、网络和凭证边界？读取宿主机凭证、访问 cloud metadata、利用代理间接出网、逃逸 SandboxOS/网络/runtime 硬隔离
持久化传播恶意内容是否进入 Memory、RAG、Skill、下一会话或其他 Agent？Memory poisoning、工具配置污染、跨会话指令传播来源、scope、过期、候选/确认态、回滚
可用性滥用是否造成循环、费用、资源或服务耗尽？retry storm、无限规划、工具调用风暴、大规模云操作预算、速率、时间、并发和熔断

08 / SECURITY ENVELOPE

Security Envelope：
给 Agent 画出可执行的边界

Security Envelope 不是一句 system prompt，而是一次任务期间 Agent 可见、可用、可传播、可持续的能力总和，以及所有硬约束。

CAPABILITY

能做什么？

工具、Skill、MCP、文件、浏览器、网络、Memory、外部消息和业务 API 的能力集合。

BOUNDARY

不能越过什么？

用户/租户/任务 scope、资源范围、时间窗口、凭证、网络出口、宿主机和数据分类边界。

EVIDENCE

如何证明发生了什么？

上下文来源、计划、工具版本、完整参数、权限决策、审批、文件变更、网络请求和最终副作用。

09 / WHY SECURITY WINS

认真做 Security，
带来的不只是“少出事故”

对个人助手来说，安全能力直接决定用户是否愿意授权真实数据、真实工具和真实生活场景。它既是风险控制，也是增长、留存和生态能力。

TRUST → ACTIVATION

敢于授权

用户愿意连接邮箱、日历、文件、浏览器和消息渠道，助手才从聊天工具变成个人生产力入口。

CONTROL → RETENTION

敢于长期使用

清晰的权限范围、审批和撤销能力，让用户知道 Agent 不会在后台持续扩大能力或改变状态。

SAFETY → BRAND

降低高代价事件

减少密钥泄露、误发消息、误删文件、恶意 Skill 和供应链事件，保护品牌与合规空间。

PLATFORM → ECOSYSTEM

让生态可扩展

Skill / MCP 有权限声明、扫描、隔离和撤销，第三方生态才能在可控边界内扩张，而不是越开放越危险。

具体场景没有安全能力时认真做 Security 后可见的业务价值
自动处理邮件恶意邮件内容诱导 Agent 转发附件或发送外部消息邮件内容视为不可信；外发动作展示收件人、附件和理由并要求确认从“只读助手”进入真实工作流，同时降低误发风险
管理本地文件Agent 为完成任务读取 `.env`、SSH key 或删除错误文件文件 scope、敏感路径隔离、读写分离、删除/覆盖可回滚用户敢把项目目录交给助手，减少人工来回切换
安装 Skill / MCP恶意插件或被替换的依赖获得凭证和工具权限来源验证、版本 pin、权限声明、隔离试运行、行为变化告警和撤销建立可信扩展市场与生态护城河
长期 Memory一次 Prompt Injection 污染下一会话或其他 Agent 的上下文来源、任务 scope、可信状态、过期、删除和回滚；候选记忆不直接生效让助手真正具备长期个性化，而不是长期积累隐患
高影响自动化付款、部署、改权限等动作由 Agent 自主执行风险分级、完整参数预览、用户/双人审批、幂等和恢复进入企业和专业用户场景，扩大可服务任务范围
一句话价值：安全不是给功能减速，而是把“不可放心授权的自动化”变成“可审计、可撤销、可逐步放权的自动化”。

对我们而言，
哪里值得先做？

安全审批与可解释执行用户需要知道 Agent 准备做什么，并能在最后一刻阻止高影响动作。动作预览、风险理由、用户确认、超时 fail-closed、审批审计低打扰的自适应审批和高风险动作的可证明策略
P2
运行时隔离与网络出口Prompt 被注入后仍要限制最坏结果；这是传统系统控制最能兜底的地方。文件/进程/网络/凭证隔离，egress allowlist，资源上限跨平台 sandbox、浏览器/代码执行安全和自动重建
P2
Agent Security Evaluation把“安全”从口号变成可回归的产品质量门槛。注入、越权、泄密、工具链和恢复测试集；安全与任务成功联合指标真实权限、长程攻击、adaptive red-team、线上 telemetry 闭环
0–3 MONTHS

先守住边界

默认最小权限 + 高风险动作审批 + Skill/MCP 供应链基线 + 可审计 trace。先让用户敢把助手接入真实生活。

3–9 MONTHS

做成产品能力

安全控制台、风险解释、记忆治理、隔离执行和回归评测。让安全成为体验的一部分，而不是后台开关。

9–18 MONTHS

建立差异化

跨工具数据流、长期记忆安全、生态信誉和自适应审批。形成面向个人 Agent 的安全基础设施。

建议对经理的结论：不要从“训练一个更强的安全分类器”开始。先把 Agent 的能力边界、权限决策、扩展供应链和真实副作用做成可见、可控、可恢复的产品面；模型型检测能力再嵌入这些确定性控制点。
